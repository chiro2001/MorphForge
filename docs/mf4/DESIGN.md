# MF4：无面捕的三通道显示协议

2026-10-20。目标是扩大每次网络提交的有效工作量，继续使用已验证的 0.25 秒提交间隔。

## 预算与速度

| 内容 | 字段 | 同步开销 |
|---|---|---:|
| 第 0 路 | `MF4_L0_D00..08`、`MF4_L0_Ctl` | 80 bit |
| 第 1 路 | `MF4_L1_D00..08`、`MF4_L1_Ctl` | 80 bit |
| 第 2 路 | `MF4_L2_D00..08`、`MF4_L2_Ctl` | 80 bit |
| 定位 | `MF_World`、`MF_Handle`、`MF_Reset`、`MF_GrabL`、`MF_GrabR`、`MF_Level` | 6 bit |
| 缩放 | `MF_Scale` | 8 bit |
| 合计 | 30 Int、6 Bool、1 Float | **254 / 256 bit** |

每路独立处理一条命令。每条绘制命令都包含完整外观，不再使用 Brush。三路同时工作时理论上为 **12 Box/s**；旧 MF3 为同外观约 4 Box/s、大量换刷时约 2 Box/s。5,000 Box 在均衡且无补发的情况下需要 1,667 个几何批次，约 416.75 秒，另加启动控制/清空批次。局部修改集中到同一路时仍为约 4 Box/s；ETA 取最长一路队列长度。

移除 VRCFT 和 MixExpressions 注入，只在 MF4 产品副本中调整。服装、道具等非 MF4 的自定义参数保留本地功能，不同步给其他玩家；VRChat 内建的人物移动、手势等不占这张自定义参数表。旧 FullFT 资产与场景保留。上传入口更新原私有诊断头像 `avtr_df2ff222-b6ff-47fb-80be-e060868596a2`。

## 单路命令

| 字段 | 意义 |
|---|---|
| D00、D01、D02 | X、Y、Z 最小坐标，8 bit/轴；X/Z 加 128，Y 不偏移 |
| D03、D04、D05 | 长宽高减一，8 bit/轴；Voxel 命令在接收端强制为零 |
| D06、D07、D08 | `style12 \| tint6 << 12 \| motion6 << 18` 的低、中、高字节 |
| Ctl 低 4 bit | 1=Box，2=Voxel，3=区域 Erase，4=精确 Remove，5=Clear |
| Ctl 高 4 bit | 本路序号，0..15 循环 |

同一 OSC bundle 内，先写每路数据再写本路 Ctl。三个序号独立推进，空闲路不推进，避免隔 16 个全局批次恢复后误判重复。各路通过 inbox 锁存载荷，再复制到不可变工作区，等待动画数据驱动稳定后擦除/出生。此协议没有 VRChat 远端 ACK；完成表示本机发包完成。

接收动画器不拆解外观的位字段。三个外观字节直接写入粒子 RGB8，Alpha 固定 255；材质的 `_WireEncoding=4` 在 Shader 中解码。粒子颜色是数据，不是可视颜色；关闭 Apply Active Color Space，使用不插值的数据传递。实际透明度、颜色、纹理仍来自上传材质目录。

## 显示池与增删

三路各有一个 5,462 容量的原生粒子池，合计最大配置 16,386；软件逻辑上限保持 **16,384 Box**。现存 Box 保留其所属路；新增 Box 分配到目标占用最少的一路。每路先删除旧几何再绘制新几何，外观覆盖保持原路；全量清空广播给三路。长方体占一个 Box；区域编辑经核心规范化后，发送器生成各池的精确删除和增量绘制。

此版本新增/更新预算回调以实际三路结构识别目标，兼容 SDK/模拟器把根对象重命名为 `Avatar(Clone)`。联合构建和上传均要求最终 37 个直接同步参数、254 bit，其他参数不能挤占或被压缩到串行槽中。

## 材质错配与兼容

发现的具体冲突：开发副本历史作品把 25/26 号定义为自定义色板，但生产 Unity 目录的 25 号是三帧、0.05 秒一帧的测试动画，26 号是六面测试贴图。OSC 只发送 ID，因此相同数字不能证明两端材质相同。

现在未导入目标目录时，使用 ID >24 的自定义材质会在入队前失败；导入后逐项比较已用材质的 UID、颜色、渲染参数、贴图与动画。目录不符不能发布，MF4 还要求显式 `mf4-three-lane/1` 能力，禁止用 MF3/MF2 向 MF4 目标发送。安装自带配套 MF4 0.8 目录按钮。目标目录只是本地声明，不冒充远端握手。

通用作品目录导出只声明材质能力；只有 MF4 构建产物或配套目标目录声明 MF4 协议。新增颜色或纹理仍需导出并重新打包头像；OSC 没有上传纹理或任意材质资产的能力。当前配套目录包含 24 基础材质、4 个历史自定义颜色、19 个原创 MIT 像素主题。

## 构建与验证入口

- `Mf4AvatarBuild.Prepare(sourceRoot)`：三个几何模块、配套材质、独立头像和场景、联合预算；输出 `Docs/MF4/avatar-catalog.json` 作为目标声明。
- `Mf4NativeSmoke.Run()`：Play Mode，真实 UDP 9012、原生参数驱动和粒子；包括覆盖、删除、重画、保持、序号回绕。
- `Mf4Visual.Run()`：GPU 像素对比与自定义颜色的时间稳定性。
- `Mf4Publish.Preflight/Start/Status`：检查证据、账号所有权、私有目标身份后上传；在 `EditorApplication.update` 启动，避免未聚焦 Editor 的 delayCall 长期不执行。
- `Mf4Analysis.Run()`：分别核验 generic、standard、security 服务端分析。

本轮不启动 VRChat、不自动切换人物、不向 9000 发送测试。多人实际同步仍需用户重新切换上传后的头像验收。
