# 分组动画与Avatar边界

2026-10-20。本轮动画在共享编辑器、截图worker、项目/作品库与GLB中实现。当前MF6头像继续显示静态草稿；播放、暂停、拖动时间轴均不会发布OSC。

本地依据：[MF6帧格式](../mf6/PLAN.md)、`crates/morphforge-core/src/mf6.rs`以及现有静态粒子存储/着色器。MF6的16种格式已经分配给几何写入/删除、局部三角带和清空；当前存储没有分组ID、关键帧表和可独立重播的播放状态。桌面中的分组名称也没有映射为网络运动槽。不能把GLB轨道直接交给现有Avatar播放。

不建议逐帧重传：它会把移动变成大批删除/重生，遇到250ms节拍、闪动及补播排序问题，且长方体无法靠现有轴对齐几何表达任意角度。预制运动比全套任意关键帧更适合作为下一步原型：先选一个少量运动槽的协议扩展，分开传入对象归属、枢轴、幅度、周期、相位和共享播放时基，在Shader中对保留几何变换。

推进条件：

1. 验证原生粒子路径能持久保存运动槽/对象归属，不破坏已有位置、RGB、PBR和三角顶点编码。槽位数按真实出生属性精度确定，不先承诺64组。
2. 为共享播放时间设计后来者可恢复的快照；时间基准和参数同步到达时间不同，不能只用每台客户端自己的启动时间宣称同相。
3. 验证变换后Bounds、法线、透明排序和跨组内部面，避免转动后消失或暴露错误遮面。编辑器动画预览已关闭静态内部面遮蔽，但这不能代替Avatar验证。
4. 先试一个旋转槽与一个平移槽，再评估轨道表/关键帧的存储成本。若需要新帧格式，应通过版本协商采用新协议，而不是复用MF6现有格式的含义。

本轮没有修改Unity资源、添加同步bit、上传头像或开展真实VRChat多人动画验收。GLB是可移植的动画作品交付路径，循环标记写入extras供播放器参考；实际播放器决定是否循环。
