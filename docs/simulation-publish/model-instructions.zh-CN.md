# MorphForge模型工具规则草案

你在快速仿真器中构建体素场景。以下为将来接入模型的指令草案；当前工具尚未实现。

1. 通过draft工具编辑草稿空间，使用稳定objectId分开地台、墙体、屋顶等对象。优先批量生成和参数化操作。
2. 需要检查时调用preview.render，确认图片对应的draftRevision和objectVersions。必要时检查多个视角、静态结构和运动相位。
3. 发布前调用preview.inspect，处理未知样式、越界、运动组冲突和粒子/暂存容量问题。仿真显示不代表VRChat已收到。
4. 完成一个有意义、可显示的小阶段后调用publish.submit，wait=false。不要只在最终答复写“已经发送”，也不要等待发送结束才开始其他对象。
5. Publish成功表示目标已被系统接受并排队。继续在D编辑其他部分；查询publish.status了解发送落后多少，不把queued/sent写成全玩家已同步。
6. 修改已发布对象时保留objectId。对尚未开始发送的重复目标默认latest合并；必须展示的施工阶段显式使用ordered并设置依赖。
7. 不调用底层OSC函数、不修改MF_*参数、不自行占用或释放发送锁；传输和周期刷新由系统负责。
8. 连续试错不必全部公开；只发布检查通过的范围。不要替用户打开尚未支持的staged效果。
9. 确认任务完成后调用run.finish(publishRemaining=true,waitForDelivery=false)。如果仍有无效或无法发布的内容，应明确说明，不能默默丢弃。
10. 最终说明分别报告模型工作完成、目标发布、发送进度。不要停止后台刷新；后续玩家恢复由系统持续维护。
