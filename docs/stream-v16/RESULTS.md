# MorphForge 0.16：发布、Avatar 材质与工作台

日期：2026-10-21。软件 **0.16.0** 已安装 gamepc 的「MorphForge - 开发测试副本」；主安装 0.15.3 及其活动任务保持原状。用户自有私有 Avatar **MorphForge MF6 16K** 已原位更新至 **v5**，generic、standard、security 三项服务端分析全部通过。未发布 GitHub Release，本轮真实付费模型请求为 0。

## 发布与协议

- 当前发送只接受 **MF6**，统一几何通道 240 bit，加定位共 **254/256 bit**。旧 MF2–MF5 发送 worker/配置入口已停用；旧工程与作品仍可读取，旧连接迁移后保持发送关闭。历史生成器和离线格式助手作为历史源保留，不是受支持的运行发送路径。
- 「自动」从**本机逐帧成功写出的记录**规划，分别完整模拟增量和 Clear 重建，并比较原分段与安全同材质长方体合并布局。模拟使用实际 `next → encode → commit`；重建包括至少两次 Clear，同耗时优先保留当前显示。可显式选择增量或重建。
- 同材质连续段用长方体的尺寸表达数量；连续变色区域可用新区域包，减少逐格坐标。规划器同时比较普通包、共享外观包和区域包，不把所有场景强制体素展开。透明、镂空、程序水云和会改变纹理周期的合并被排除。
- 手动「保留显示补播」绕过自动清空策略；连续/周期补播不清空。Harness 的 `publish(repair=true)`、`loopReplay` 已接到 MF6 路径，并覆盖回归。
- 新增发送进度条：当前几何计划已发帧/总帧、百分比、剩余时隙估算。补播每轮重新计数；进度仅表示本机 UDP 写出。

### 连续区域包

保留 30 字节帧；`MF6_D00..28` 为29个 Int，`MF6_Ctl` 为一个 Int。Ctl 高4位为序号、低4位为格式；区域扩展使用格式0及数据魔数区别 Idle。

| 字节 | 内容 |
|---|---|
| 0–2 | 原点 XYZ，各8 bit |
| 3 | 扫描形状2 bit、数量减一3 bit、共同表面模式3 bit |
| 4–27 | 最多8项独立24 bit外观（颜色或目录/表面编码） |
| 28 | `0xa8 | first_pool` |
| 29 | 序号与格式 |

扫描支持 X/Y/Z 线段与 X 快轴的 2×2×2 小块。每包含原点、顺序和外观，不依赖上一包的游标或色板；丢包不会把后续坐标整体错位。每帧最多8格，与8个原生池匹配；没有实现通用压缩或执行 ACK。

### 真实规划器的合成基准

以下是4096格测试场景，时间按400ms节拍换算，不是 VRChat 实际接收耗时。完整数据：[publish-benchmark.json](publish-benchmark.json)。

| 场景 | 原方案 | 所选方案 | 估算变化 |
|---|---:|---:|---:|
| 连续位置、逐格独立 RGB | 普通包1366帧 | 区域包512帧 | 546.4s → 204.8s |
| 全场替换 | 增量1536帧 | 两次Clear＋重建514帧 | 614.4s → 205.6s |
| 4096个同色单位格 | 原分段 | 合并成1个长方体、1帧 | 不是发送4096个单格 |

动态任务中每次发布都重新比较，不能据此承诺任意5000对象作品都能达到相同速度。

## Avatar 能力识别与材质关系

Avatar 增加不同步的 `MF_InfoVersion`、`MF_InfoFeatures`、构建号和32个目录哈希字节。Windows 自动寻找 VRChat 的 OSCQuery 端口，连续读取两次能力常量；也可手工指定查询端口。默认15秒轮询，可关闭。检测到 Avatar 改变会停止当前发送并使旧基准失效。

目录身份使用跨 Rust/C# 一致的二进制 SHA256，包含实际材质渲染定义与纹理构建选项；不依赖 JSON 字段顺序或浮点文本格式。当前真实 Avatar 哈希：

`5dde40a53705beee432145e5cfe00c937c1b55097261861588b3ae5e9c61cab8`

本机按哈希缓存目录；未知目录不会自动套用其他头像的贴图。Avatar 参数只能声明身份和能力，不能把贴图文件下载到编辑器，因此另一台电脑仍需导入匹配的构建包或自己的资源包。gamepc Preview 已私下预置当前目录、PNG与原版方块状态索引，点击「把 Avatar 材质加入项目」即可使用；操作保留既有几何和材质ID。

该查询**不读取执行计数、不作为 ACK、不确认其他玩家接收**。真实 GestureManager 已验证能力默认值/哈希，Windows 界面通过本机 OSCQuery HTTP 夹具完成识别流程；本轮没有替用户切换真实 VRChat 客户端，因此仍需用户重切头像后现场确认真实客户端发现。

## Minecraft 原版材质：已经纳入私人 Avatar

使用 Mojang 官方 Java **1.21.1** client JAR，核验其官方 SHA1 `30c73b1c5da787909b2f73340419fdf13b9def88`。导入1142项材质定义，与既有544项合并为 **1686项**；最大 style ID1725，当前有1662项图片材质、67项动画材质、178项透明、375项镂空。它们是**材质定义**，不等于完整模拟1686种方块几何或游戏行为。

支持完整立方体六面、草方块叠加层、固定默认植被染色、90度面纹理旋转与常见动画。按 PNG 实际 alpha 修正65项玻璃/冰等表面分类。非立方体模型、复杂 multipart、CTM、生态群系动态染色和超长动画周期仍有限制，报告保留近似信息。

### 存储与显示开销

不按材质增加 Animator 层或粒子系统；方块仍只传目录 ID/染色/表面描述。纹理按实际图像去重，face-map 间接索引到 Texture2DArray，最多4组、每组2048层。支持16/32/64像素构建；当前使用16像素、mipmap、两组数组、3258个去重纹理层，兼容平面图集缩为1×1。

| 项目 | 测量/估算 |
|---|---:|
| 原版导入＋24基础材质，16像素 | GPU纹理约 **4.49 MiB** |
| 同一目录，32像素 | GPU纹理约 **16.99 MiB** |
| 当前1686项合并目录 | 3258个独立层、2组数组 |
| 合并目录 Unity 数组内存报告 | **8,888,736字节**，含CPU可读副本及Unity开销 |
| 合并目录元数据／face-map报告 | 524,968／160,424字节，同样是Unity驻留内存报告 |
| 新增同步bit／动画器层／粒子系统 | **0／0／0** |
| v5完整人物Avatar SDK压缩文件 | **11,416,038字节**，不是仅材质包的大小 |

GPU预算与 Unity 的驻留内存报告口径不同，不能把后者直接当成显存；完整人物 Avatar 还含人体和其他资源。预算文件：[16像素](vanilla-budget-16.json)、[32像素](vanilla-budget-32.json)、[实际合并构建](catalog-unity-build.json)。

原版 JAR/PNG/完整私人目录只留在私人本机数据和 Unity 工程；不放公共仓库、不内嵌公开可执行程序。公开软件仍内置原创 Minecraft 风格资源。新图片仍需重建/上传 Avatar；已内置目录可直接选用和染色。

### 建筑导入精度

不再默认每个 MC 方块边长4格。`blockScale=0` 自动按使用到的形状选最小整数格精度：整方块1、半砖通常2，薄装饰可能更高；同时尽量适配256格目标空间，优先降低精度并明确报告薄细节量化。可显式选1/2/4/8/16。每MC方块边长4格并不必然生成64个显示对象：完整块始终可为一个长方体，邻接同材质还能合并；它主要扩大坐标范围和细节精度。

预览返回实际 `blockScale`、所需无损精度、是否因目标空间限精度、量化对象数和容量/越界报告。源建筑文件保留；不静默丢掉薄结构，也不承诺超出256格的完整地图能自动缩入。

## 工作台验收修复

- 艺术预览/VRC虚拟光照切换按格长及物理缩放同步相机位置、观察中心和正交范围，保持原来的构图；把渲染模式纳入加载签名，修复切换撞上轮询后不生效的问题。
- 树叶等 cutout 材质显示双面，使透空处能看到方块远侧背面；普通不透明表面维持原有裁面。生产 WebGL 和真实 Animator 生成粒子的 GPU 像素检查通过。未收到更具体的树叶异常描述，因此不宣称排除了所有资源包/远距离过滤问题。
- 输入框旁新增「建模类型」：模型决定／体素／多面体／混合，以及自动／32／64／128／指定XYZ格数。默认由模型决定，保持作品比例；偏好进入动态上下文，不重写历史请求前缀，不自动缩放现有作品。发送消息前等待偏好保存。
- 工具schema升级至4.2。旧对话继续保留其冻结的工具/提示词；新开对话可直接使用最新说明，显式升级旧对话会重新预热缓存。
- 作品库用户作品有「删除」，共享条目移到 `artwork-trash`，保留资源和当前工程；内置示例只读。其他实例刷新即可看到删除结果。当前没有图形回收站恢复入口，可从该目录取回JSON。
- 定位球增加两个专用手部 ContactSender 和匹配的本地自接收器，沿用握拳抓取/松手逻辑，光球抓取时继续显示。新增同步bit和Animator层均为0；真实VR手部与多人抓握仍需现场验收。

## 多实例

重复启动会使用独立的持久工作区/工程/上下文，空闲实例目录可复用恢复。作品JSON与资源共享；保存原子发布，资源先入库，避免另一窗口读到半张图片。每个原生窗口拥有独立 WebView2 profile；修复了环境变量覆盖profile路径导致第二窗口失败、关闭第一窗口带走第二浏览器的问题。Windows用操作系统排他文件租约复用空闲缓存槽，避免每次启动都累积一份浏览器缓存；崩溃退出也由系统释放租约。

OSC使用同一个Windows用户目录下的文件锁排他。第二实例可以编辑和生成，发送被占用时明确报错；旧实例停止发送释放后可接管。它不抢占正在发送的主安装，不把独立实例的计费日志或活动AI任务复制过去。

## 验证与限制

- 最终 Rust/Node/Windows/浏览器汇总见 [validation-summary.json](validation-summary.json)。Rust工作区251项、Node58项、Windows原生界面22项、真实多窗口16项、Chromium新增工作台16项及Minecraft导入10项通过；均未打开OSC或调用模型。
- 新区域原生验证：98帧、400ms节拍、连续变色最终512粒完整；普通协议回归177帧。4组纹理数组292项GPU检查、共面深度29项、树叶2项、抓握5项通过。
- 区域测试暴露生命周期和数据输出时序错位导致误删8粒，已修复本地driver与phase输出；失败证据保留。同步位和层数不增。
- **250ms曾漏16粒**，不能因本机正确就宣称多人可靠。400ms证据也只是本轮Unity环境，不保证真实多人无损。继续提供0.10/0.20/0.25/0.28/0.30/0.40/0.50秒档及补播。
- 本轮最终worker没有重跑完整16K长时容量，16,384是当前配置容量，不是新的无损长时验收结论。
- v5三项服务端分析通过不等于真人已换装或多人接收通过。证据：[avatar-analysis.json](avatar-analysis.json)。
- 执行ACK、碰撞、Avatar动画明确不在范围；编辑器/GLB动画保持已有功能。

## 用户测试顺序

1. 打开桌面「MorphForge - 开发测试副本」，确认0.16.0；原主安装仍是0.15.3。
2. 在VRChat重新切换一次 **MorphForge MF6 16K**，加载v5；工作台点击「识别当前Avatar」，确认目录匹配。
3. 点击「把Avatar材质加入项目」，从材质中选原版/原创MC材质。Minecraft建筑导入可选择对应原版包，先检查自动格精度与近似报告。
4. 需要从新副本发送时，先在原主程序停止OSC，再开启副本发送。看进度条并测试小改动/大替换自动选方案；补漏用保留显示补播。
5. 检查预览切换构图、树叶透空、输入区偏好、作品删除，以及光球可见时双手握拳抓放。完成后再扩大到多人场景。
