# Avatar 性能与本人预览（2026-10-24）

用户已确认上一轮动画方向和循环在 VRChat 中正常，本轮以此作为回归基线。

## 改动

- `本人预览` 安装到 `MorphForge` 子菜单；手部跟随、保持水平及抓握移入 `定位设置`，避免菜单超过八项。重复安装检查会递归查找已有抓握控件。
- 默认相机位于模型坐标的正 Z 侧，水平朝向原点，与 Desktop 正视图一致；斜视仍可选。默认关闭，未增加同步位。
- 保留两组动画接收缓存，材质只输出当前选中的一组。动画材质属性绑定由 3,132 降到 1,656；常量系数合并，缓存接收仍由原来的 123 个完整 WD On 状态持有。
- 关闭的动画、空白文字使用普通 WD Off 空闲 Clip；完整 Direct Blend Tree 保持 WD On。文字缓存独立保留，未加入对应动画组的文字不输出整套关键帧。
- 十六个私人/公共几何控制器的空闲状态只写三个开关，准备及发射阶段仍完整写入原生粒子数据。

## CPU 对照

同一 Windows 机器、同一人物与 SDK 处理流程。旧版使用修改前备份控制器，其他人物资源保持一致。以下为 Unity `Animators.Update` 的每帧 CPU 耗时，不是 VRChat FPS。

|场景|旧版平均|新版平均|
|---|---:|---:|
|冷启动空载，本人预览关闭|6.54 ms|5.46 ms|
|三组四关键帧动画，本人预览关闭|11.28 ms|9.04 ms|

空载约减少 16%，三组动画约减少 20%。删除整个模块的独立诊断为 0.93 ms，删除动画模块为 3.00 ms，删除文字模块为 5.28 ms；这些是构建前移除部件后的诊断，不能与仅关闭层权重混同，也不能将各次差值相加。[消融数据](static-ablation.json)。

首次恢复 Editor 时采用了 batch 模式，该环境中的旧、新控制器都在 250 ms 发送节拍下出现接收不完整。相关数据不用于最终功能验收；恢复交互式 Editor 后，两版相同节拍均通过。

## 验证

- SDK 处理后的四轮旧旋转/新 Y-/Z+ 平移替换：492 个材质值与 24 个 GPU 位置对比通过。
- 自由推进的原生时钟连续运行：三组各循环三次，106 次 GPU 位置对比通过，无反向步骤。没有手动修改相位或材质代替播放。
- 文字缓存、分页、字幕代际、零值覆盖和几何保持共 15 项通过；原生点线绘制通过。
- 动画接收、启停/暂停/恢复、换缓冲、GPU 姿态、恢复重建、三角面/文字联动和单次播放通过。
- 本人预览九项检查通过，包括关闭后相机停止、六种位置、正视方向、缩放和排除自身面板。
- 公共模块的独立安装、重复安装、菜单压缩和预算防护六项通过；独立预算 253 bit，加服装控件压缩后 256 bit。

材质仅在控制更新时采样的隔离原型约为 8.42 ms，较当前方案只减少约 0.6 ms，但需要更多状态和参数，因此本轮未采用。

## 实机范围

已保存当前头像、项目、动画、发送与预览状态。当前会话使用无线串流，VRChat 保持运行。现有 SDK 登录可访问头像选择 API，不导出登录凭据。

SteamVR 新客户端握手返回 `InitError_Init_NoServerForBackgroundApp`，客户端日志显示等待 `SteamVR_Namespace` 命名管道超时。只读采样脚本已准备，可区分应用帧间隔、GPU 时间及重投影。另已验证可以通过 Windows 读取游戏画面且保持桌面焦点；当前快捷菜单没有 FPS 数字，后台鼠标消息未改变 VR 菜单。实机 FPS 对照尚待可读取的性能显示或运行时采样恢复，不能以 Editor 耗时冒充实机结果。[采样限制](vr-frame-sampling.json)。

不重启 VRChat 或串流，除非用户补充授权。桌面程序继续使用 0.26.1；不调用真实麦克风或付费模型，不推送或创建 Release。

公共包 `dist/avatar/MorphForgeAvatar-1.3.2.unitypackage` 为 6,102,366 字节；160 项资源与源码一致，54 张原创 PNG 哈希通过，不含私人绑定、商业人物或用户变体。[包审计](package-audit.json)。

现有私人头像更新为 **v13 / file v11**，ID、名称、可见性保持一致。generic、standard、security 三项服务端分析均通过，仍为 VeryPoor；容量上限和服务器统计中的最大粒子面数没有降低。[线上信息](online-avatar.json)、[服务端分析](online-analysis.json)。

最终 SDK 合并为 152 层、1,926 个 FX 参数、254 bit。菜单路径确认为 `root/MorphForge/本人预览`，没有超过八项的菜单；普通空闲 Clip 为 WD Off，完整 Direct 输出为 WD On。13 个人物原 Prefab 依赖保持不变，上传后恢复干净源场景。[构建审计](built-audit.json)、[源资源](source-final.json)、[恢复](source-restored.json)。

SDK 认证的头像选择 API 返回成功，但游戏端未观察到对应换装。随后通过本地 OSC `/avatar/change` 切到另一个自有头像并切回 MF6，OSCQuery 分别确认两个 ID；未重启串流。[客户端换装](client-reload.json)。恢复主程序发送及当前项目 revision16、creative revision1、`flow-loop`；重发前后作品场景数据一致。MF6 重载会重新建立临时世界放置，缩放和定位控制由原设置恢复。

换装 ID 出现后仍需等待 MF6 参数恢复，才能重发作品。确认 `MF_InfoVersion=9` 与本人预览参数实际存在后，已重新完整发送模型和动画，最终队列为零、sentRevision16、动画 state1，作品场景与重发前一致；发送和定位开关保持原值。这是本地 UDP 发送完成记录，协议没有远端执行 ACK。[重发记录](client-publication.json)。

实机本人预览探针成功开启预览并捕获游戏窗口，画面中可见瀑布正面；结束后再次读取 OSCQuery，确认本人预览恢复原来的关闭状态，桌面焦点未改变。实机截图保留于私人临时目录，不包含在公共包或本仓库。[开关恢复记录](preview-client.json)。Unity 保持已上传后的干净源场景，VRChat、SteamVR 与无线串流未重启。
