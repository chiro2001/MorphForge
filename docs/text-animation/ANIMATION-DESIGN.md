# 动画方案草案

日期：2026-10-22。状态：供讨论，尚未实现或部署。

## 目标与当前基线

以“发送动画定义和播放状态、Avatar本地连续求值”为主要路径，降低逐帧重建几何的OSC开销。支持体素、三角面、体素文字与贴图文字，允许AI调用同一套API。

已存在的编辑器Clip/Track/Keyframe模型、分组播放、姿态截图和动画GLB导出可以作为作者侧基础，见`crates/morphforge-app/src/creative.rs`、`web/motion.js`与`creative_schema.rs`。现有工具说明明确MF6只发布静态几何，并没有Avatar动画轨道播放器。不能把编辑器已播放当作Avatar已支持。

官方参数同步规则：https://creators.vrchat.com/avatars/animator-parameters/ 。Playable同步按需约0.1至1秒，不能依赖其逐帧动画。Unity的_Time是本机加载后的时间，不构成跨客户端共同播放时钟：https://docs.unity.cn/jp/2022.3/Manual/SL-UnityShaderVariables.html 。

## 三类动画与落地顺序

| 类别 | 第一阶段候选 | 后续扩展 |
|---|---|---|
| 文字效果 | 静态/滚动/闪烁/逐字显现 | 字符波浪、渐变、淡入淡出 |
| 材质效果 | 帧贴图、颜色/发光脉冲、UV滚动 | 多属性短关键帧 |
| 几何运动 | 分组平移、旋转、缩放；匀速旋转、往返/摆动 | 有限关键帧片段、多个动作切换 |

这些是显示侧效果，不提供碰撞、物理模拟或任意脚本执行。文字默认体素；只有明确选择贴图文字时才作用于贴图文本框。

## 对象绑定与数据流

1. 静态几何照常上传，保留稳定ID与基础姿态；组成员另绑定motionGroupId。
2. 发送有限动画组的定义：枢轴、效果类型、轴/幅度/速度或周期、相位、循环规则，以及有限关键帧等。
3. 发送可重放的播放状态：定义版本、playing/paused/stopped、速度、播放位置。补播不能重启已在播放的同版本动作。
4. Animator接收和保存定义/状态，有限的本地时钟驱动播放；Shader按组求值并变换顶点、法线或文字外观。仍需验证Animator与Shader之间的数据保持和读取方式。
5. 只有定义、组绑定或播放状态变化时占用OSC；运行中允许低频相位校正，不逐帧发送每个Box的位置。

目标是共享现有240bit数据通道，增加消息类型和接收端存储，不为每个动画组新增同步参数。动画定义、文本和几何仍竞争带宽，需明确调度优先级、分段重发与原子提交策略。

## 第一阶段容量和实现验证

- 从8或16个有限动画组原型起步，正式容量依据位预算、材质属性、Animator帧时间与GPU测试确定；不承诺现有64条编辑器轨道都能直接发布。
- 单个组可以包含很多Box/三角面，动画定义成本主要跟组/关键帧数有关；成员关联仍有初次传输成本。
- 必须解决粒子中持久化groupId：现有颜色/形状/位置字段已有用途，不能假定免费字段；需要比较新增绑定格式、粒子流/元数据字段和固定池分组，测量容量与材质语义代价后再定。
- 比较Shader时间函数与少量按组Animator本地播放时钟，测量层数、状态与CPU成本；不采用逐Box一层Animator。
- 新组定义采用准备版本与有效版本分离，完整收到后启用；内容补播幂等，组ID复用需防止旧几何错误绑定。
- 现有运行中Avatar不能动态生成任意AnimationClip/纹理资产；必须上传预制的通用播放器、Shader和有限存储。普通新作品在已支持能力范围内只发数据，超能力扩展才需要重新上传Avatar。

## 播放时间与晚加入

不能直接把_Time当共同时间源。需通过本地播放器和带版本/播放位置的状态重建来恢复播放，测试低频校正能达到的相位误差。先承诺自主平滑播放，不承诺所有玩家逐帧严格同相。

- 晚加入者先恢复几何和动画定义，再恢复播放状态；允许分组分阶段可见。
- 循环补播定义不能把每圈变成重新开始；replay/restart应是明确的新版本/命令。
- 暂停保存播放位置；继续从该位置启动；停止行为区分停在当前与恢复基础姿态。
- 同一组的成员晚到也应加入当前组姿态，不能每来一个粒子就从零开始。
- 缺少定义时保持基础姿态，不能按残缺字段错误旋转或缩放。

## 自由关键帧

保留编辑器较完整的关键帧作者功能；Avatar第一轮只发布受限片段，不能静默降级。

- 优先实现有限组、有限关键帧的平移/旋转/缩放，循环、往返、step/linear等。
- 坐标、角度、时间与缩放需声明量化精度和范围；旋转插值在编辑器/Shader保持一致。
- 后端分析Clip是否能转换成更短的旋转/正弦/往返描述；转换超出误差阈值时不替换。
- 任意每帧几何变化、复杂角色骨骼/蒙皮与长时间高频流暂不纳入首版。可以在编辑器继续制作/导出，但发布时明确能力差异。

## 用户与AI操作

- 选择对象/分组→设置枢轴→添加效果或关键帧→本地预览→检查→发布。
- 底部时间轴支持播放/暂停/停止/拖动、速度和循环；属性面板开关与Unity导航遵循需求记录。
- AI通过动画工具创建/修改、查询容量、指定时刻截图、播放/暂停/定位。定义与播放状态有独立revision，避免动画播放不断改变几何revision。
- 文字内容更新与文字运动独立，新增字符继承当前文本框动作，避免每次识别partial都重启滚动/淡入。

## 验收

- 字幕滚动与新字符连续更新；体素风车绕正确枢轴旋转；门开合；三角面分组移动。
- 编辑器、Unity、Avatar对比固定播放位置下的几何/法线/虚拟光照与文字裁切。
- 执行隐藏、选择、擦除、增量发布时按基础存储与稳定ID处理，不把Shader位移后的画面坐标混入底层删除地址。
- 计算运动包络，检查整个动画周期是否越出目标空间；适配器规则需明确，不能只验静止初始姿态。
- 扩大粒子可见性包围盒以覆盖运动，验证遮挡/裁剪、透明排序、多池和缩放；反向/非均匀缩放需限制或正确处理。
- 测试消息丢失、乱序、重复、Avatar重载、晚加入和不同FPS；记录相位误差、恢复时间、接收吞吐与CPU/GPU开销。

最终字段与容量在原型验证后冻结，不在讨论阶段宣称新的显示/同步能力已完成。
