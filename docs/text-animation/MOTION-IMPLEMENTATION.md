# 原生分组动画与本人预览实施记录

2026-10-22，Desktop 0.21.1 / Avatar 1.2.0 候选。功能和验收已完成，主安装更新至0.21.1；本轮不发布GitHub Release。

## 动画 API 与限制

保留现有工程的动画编辑、截图和 GLB 导出能力，增加显式 Avatar 发布。AI 和桌面按钮共用 `animation` 工具：

| action | 用途 |
|---|---|
| publish | id 为已保存片段；speed 默认1；position 默认0秒；playing 默认true；dryRun可仅检查 |
| play / resume | 从当前保存位置继续；可传position定位 |
| pause | 暂停在当前或给定位置 |
| stop | 回基础静态姿态，默认位置0 |
| seek | position以秒计，保留播放/暂停状态 |
| status | 当前片段、组绑定、位置、队列及明确的无远端ACK状态 |
| detach | 解除绑定，重发当前草稿为静态；保留版本历史并补播停止指令释放旧播放器 |

Avatar首版最多3个运动组，每组4关键帧。第0组为静态。支持step和linear，旋转为最短路径四元数插值，完整转圈需中间关键帧；支持1/16..8倍正均匀缩放。时长0.125/0.25/0.5/1/2/4/8/16/32/64秒；速度0.25/0.5/1/2。编辑器/GLB原有64轨道能力保留；Avatar超限明确拒绝，不默默丢轨道。关键帧量化后重合也拒绝。

整个运动包络（Box角点、三角顶点、文本框角点，包含连续旋转中间态）须在X/Z[-128,128]、Y[0,256]中。状态验证在改变发送目标之前完成。自动合并不跨分组，候选合并布局也保留动画绑定。

## 串联方式

仍是240bit单发送器，不新增同步位。几何保留位承载组号；新扩展op16/17/18承载定义、关键帧、控制。完整字段见MOTION-WIRE-DRAFT.md。文本样式D13绑定同一组。动画定义与时钟只发送一次/补播；动画每帧由原生Animator和Shader在本地推进，不逐帧传顶点。

每组双bank。新定义必须收齐header与所有所需key才能切换；旧bank继续显示。ticket使重复控制/盲补播不重启动画，控制phase在实际发送时计算。循环使用frac，单次使用saturate；原生elapsed 0..1加phaseBase，避免Unity非循环Clip忽略cycleOffset。Clear清除旧版本、时钟票据和就绪状态；重新连接/清空重建会重播定义，程序重启后可用初始代次重新建模。

控制验证可能在route最后一帧完成，因此apply允许在稳定Stage0执行，并排除新快照Stage1，修复低帧率丢控制。播放端20层、472状态、734本地参数，0新增同步参数。这些本地参数仍有CPU/构建成本。

Box用出生Color32 Alpha保存材质模式、斜面和组号；Rotation3D保存原中心，Shader恢复根基底再施加TRS。三角面变换原顶点；文字先排版再施加相同组TRS，双面布局仍可读。已发送记录保存组号，重新绑定只重发受影响几何。实时短文字与几何/动画共用队列，短窗仍按至少两个发送间隔节流。

Capability为`mf6-motion4/1`，本机InfoFeatures bit6识别；未确认真实9000目标能力时拒绝发送。能力识别不是网络执行ACK。跨玩家动画相位不保证严格一致，丢包仍依赖补播和用户选择间隔。

## 本人头边预览原型

可选Camera→512×384、2x MSAA RenderTexture→头边面板，默认关闭。拍摄Avatar实际已接收的几何/文字，不复制粒子状态、不给外部草稿冒充接收状态。摄像机随作品锚点和缩放移动，使用透视取景避免orthographicSize不跟Transform缩放的问题。

本地参数MF_Preview、MF_PreviewCorner、MF_PreviewSize、MF_PreviewZoom、MF_PreviewOblique；菜单提供开关、左/右/四角、大小、取景缩放、正面/斜视。IsLocal为false时相机和面板强制关闭。HeadRig通过原生约束跟随MA HeadReference，屏幕不直接放在Head骨骼子树中，避免直接受到第一人称头部子树隐藏。界面Shader在镜子/拍照相机标志下隐藏。

已做Editor合并Avatar验证；VR头显左右眼、舒适度、真实客户端第一人称/镜子/拍照仍需用户实机确认。当前相机不是只绘制作品的隔离相机，可能拍到取景范围内人物/世界。默认全空间取景，小作品应调缩放；额外相机在启用期间增加GPU开销。未实现SteamVR HUD或低频调度承诺。

补充：固定本人身份下，正常开关/调整预览后继续Clear+重建已通过。模拟器中强制把IsLocal来回翻转后曾产生渲染属性回读不一致，故身份门控检查与固定身份连续播放检查分开进行；不为这一模拟条件加入未经证实的播放器补丁。公共模块完整receiver/dynamics/GPU/recovery四段连续套件已在干净Play通过。

最终补充：单次动画从半相位开始并停在末帧，GPU末姿态宽64像素；三角面中间姿态宽160→113、左边界176→240符合平移/旋转；文本共享旋转从9088墨点到90度边视0墨点。整个Avatar的Editor Animators.Update采样，关闭动画输出层权重约5.97~6.16ms，空闲门控约6.27~6.28ms，3个已填充bank约7.79~7.90ms；包含其他基础动画/文字，不能当独立动画增量或客户端FPS。Motion controller YAML20.8MB，原始对象内存估计14.4MB，均不是Avatar下载体积。

补充改稿语义：绑定动画后的每次发布都会重查运动包络，失败不改发送目标。停止播放保留绑定供继续；detach清空几何/文字组绑定、重发静态草稿，同时保留bank/代次/ticket历史，下一次发布动画不会被接收器误判为旧重播。旧组的停止票据也会补播，避免无几何引用时仍保持播放器活跃。AI运行时可手动暂停/继续已发布动画，手动publish/detach仍遵守编辑锁。

编辑器文字也纳入同一分组TRS，重复预览不累积变换，退出预览恢复原矩阵；文本框参与动画视角边界，纯文本场景可导出含分组动画的GLB。实际Chromium验证覆盖这些情况。本人预览相机使用特征投影范围让面板Shader排除自身画面，启用/禁用面板的两次相机渲染像素完全一致，防止RT递归反馈（Editor验证）。
