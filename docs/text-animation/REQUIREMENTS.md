# 贴图文字、语音输入与下一轮交互需求

记录日期：2026-10-22。状态：设计记录，尚未实现；动画方案等待后续讨论。

当前基线为 Desktop 0.16.1、Avatar 插件 1.0.0。以下内容不代表现有版本已支持，也不代表已经完成 VRChat 实测。

## 1. 文字显示与字库方向

- 保留现有的“文字生成体素 Box”，新增独立的贴图文字对象，用于实时字幕、说明牌与动态状态。AI 需要能够调用两类文字 API；默认使用体素文字，只有用户明确要求贴图文字/字幕，或任务配置明确指定时才使用贴图文字。
- 字形优先采用 8×16 半宽、16×16 全宽二值点阵，不做字形灰度平滑；文字颜色、透明度、发光与字形掩码分离。
- 候选存储方式为 R8 中每字节打包 8 个逻辑像素；16,384 个 16×16 字形的基础像素载荷为 524,288 bytes，不含元数据、CPU副本或构建包装。需要验证 Unity 导入后的真实格式、逐点解码、显存与 Avatar 下载增量。
- 兼容 ASC16/HZK16 导入；中日英统一通过 Unicode 到字形编号映射。日文候选为 Jiskan16 / Unifont JP 等，最终覆盖、字形地区变体与发布许可在实现前核实。
- 外部 Rust 负责规范化、分行、换行规则、段落和行宽；Shader 依据同一字形宽度表累计行内位置。半宽=1、全宽=2；按字形元数据判断，而非按中文/英文粗分类。
- 实时短窗口优先显示最新状态，合并过时的待发更新；持久长文本按对象/行分页更新与补播。
- 240bit 下的“14个16bit字形”只是候选快照载荷布局；未包含最终所有地址、样式和完整性设计，不能作为已实现吞吐保证。

## 2. 编辑器文本框

用户要求：能创建文本框，在编辑器中上下左右移动，在框内渲染文字；有默认位置、默认字号，能明确配置一个字相当于多少逻辑格；提供实际文字输入框。

建议将文本框作为独立的场景对象：

- 新建、选择、重命名、复制、删除，支持撤销/重做与工程保存。
- 拖动平移手柄控制上下/左右/前后；检查器可精确输入 XYZ、朝向与尺寸；支持网格吸附。
- 框的宽高使用作品逻辑格单位；字号以“一个全宽字的高度占多少格”表示，16点字体下全宽字宽与高一致、半宽字宽为其一半。
- 排版、字号与整体 Avatar 缩放分离；点阵可在连续坐标中显示，不必强制每个像素占一个整数体素格。
- 字体、字号、字距、行距、对齐、背景、文字颜色与溢出规则都有默认值，并可保存为预设。
- 检查器内提供多行文字输入区，选择目标文本框后编辑对应内容；实时预览与网络发送解耦，并显示发送状态。
- 文本框边框、选中框和拖动手柄属于编辑辅助，默认不随文字显示到 Avatar。

建议初始预设（待实现时验证后冻结）：

| 设置 | 默认建议 |
|---|---|
| 平面 | XY，朝向编辑器正面预设 |
| 定位点 | 文本框底部中心 |
| 位置 | [0,24,0] 逻辑格 |
| 宽高 | 128×32 逻辑格 |
| 全宽字号 | 高8格、宽8格；半宽宽4格 |
| 对齐 | 左对齐、顶部对齐 |
| 普通文本 | 自动换行，超出范围裁切并提示 |
| 字幕预设 | 底部对齐，保留末尾行；固定字号，避免反复缩字 |

文字对象应有独立数据模型，不能通过隐藏 Box 假装成文本。其占用的字符槽、对象槽和协议能力需要单独声明并计入目标发布预算。

### 2.1 正反两面均可读

用户明确要求文字前后两面都显示为可识别的正面文本。

- 贴图文本框默认双面可读，背面校正布局方向与字形采样，不能仅关闭背面剔除就把镜像字当作完成。
- 从正面和背面各自观察时，都按同一内容正常从左到右阅读；不只翻正单个字，还要纠正整行字符顺序。多行顺序和半宽/全宽布局保持一致。
- 正反两面共享内容与样式；滚动、逐字显现、局部更新等效果都遵守观察侧的正常阅读方向。
- 优先由同一文本对象/几何的Shader处理观察侧，不为背面重复发送字符，避免额外OSC载荷和共面重叠闪烁；实际Shader/透明排序效果需验证。
- 体素文字属于真实几何，单一挤出字形从背面天然会镜像；需要双面可读时采用独立的前/后可读字面或专门标牌结构，计入额外Box/面/厚度预算，不能用普通Cull Off宣称已解决。
- AI工具说明需区分贴图双面排版与几何文字结构；体素文字仍为默认生成类型。
- 验收覆盖非对称字母、数字、中日英混排、多行、斜视与文本框旋转，检查字形和整行顺序，并验证两侧截图一致表达相同内容。

## 3. 语音输入：两个输入目标，共享识别服务

用户要求参考已有 vrc-chat-tool，支持在线模型与单句离线模型；既能输入显示文字，也能输入建模指令。

只读核查结果：

- Linux 参考源码：`/home/chiro/projects/vtc-chat-tool`（目录名是 vtc，工程自身为 VRC Chat Tool）。
- Windows 参考源码：`D:\Projects\vrc-chat-tool`；另有 next / old 目录，本轮未把它们作为已验证来源。
- `src-tauri/src/speech/recognizer.rs` 统一部分结果与句末结果回调，源码包含腾讯云、远程 WebSocket、本地识别与本地混合识别。用户已确认远程 STT 不可用，不纳入 MorphForge 的可用后端、默认配置或自动回退路径。
- `src-tauri/src/speech/local_embedded.rs` 提供本地嵌入式入口；`crates/stt-server/src/hybrid.rs` 使用 Zipformer CTC 流式识别、SenseVoice 句末校正。
- `src-tauri/src/audio/capture.rs` 可参考录音、音频格式转换与停止控制；`crates/stt-server/src/config.rs` 可参考模型配置。
- Windows 本地凭证文件存在，环境变量形式的三项腾讯配置名存在；本轮只检查文件与字段存在性，未输出密钥，未验证凭证有效性，未调用云服务。
- 参考工程使用 Tauri v1，MorphForge 使用 v2；抽取采集/识别逻辑为独立 Rust 服务，不直接复制其 Tauri 命令绑定或全局状态架构。

计划接口与交互：

1. 两处输入框均有麦克风按钮，支持按住说话/开始停止、设备选择、取消、识别中和出错状态。
2. 在线后端先参考已有腾讯云；远程 STT 排除。这里“在线云服务”和“流式识别模型”是两个独立维度，界面不混称。在线识别前必须先运行本地 VAD，避免将长时间静音持续上传或维持不必要的计费会话。
3. 离线需要对比评估 Zipformer 流式识别 + SenseVoice 句末校正，与本地 VAD + SenseVoice 单句识别两条路径。若混合方案的时延不佳，则只保留句末模型作为默认离线方案。当前混合引擎内已有 SenseVoice，但仍需抽取/验证纯单句调用接口。
4. 统一产生 sessionId、目标、partial/final/cancel/error。partial 仅替换当前临时片段；final 根据设置替换或追加，不能每次 partial 都重复追加。
5. 录音开始时固定输入目标，避免用户切换选择后文字落到另一个框；手工输入与识别结果使用片段标记合并，不覆盖用户同期修改。
6. 建模输入默认只填入草稿，由用户点击发送；新增可选关键词触发提交，例如可配置的“开始建模”。开启后，只在最终识别文本确认关键词及对应指令后提交，不能由 partial 重复触发；去掉触发词后保留实际指令，空指令不提交。AI 正在运行时沿用现有插话/排队路径，不能隐式创建冲突任务。
7. 文本显示输入可选择实时字幕模式：partial 更新最新窗口，final 提交句子；受网络带宽约束，保留最终值和后台补播。
8. 模型下载、路径、语言、识别后端与凭证统一放设置页。凭证仅本地保存；不得写入工程、作品库、截图、日志、Git或安装包。

### 3.1 时延与资源评估

- 使用相同音频、设备、VAD配置和中日英目标语料，对比两条离线路径，覆盖短指令、连续口述、停顿、噪声与句末补词。
- 分别记录冷启动/模型加载、首次部分结果、说话结束到最终可用文本的 P50/P95、识别质量、CPU/内存，以及最终结果送达输入框和关键词提交的额外耗时。
- 检查流式解码与句末校正是否阻塞下一句录音，避免校正速度表面正常却产生排队积压。
- 不以“有流式中间结果”直接判定更快；建模指令以可安全提交的最终结果时延为主要比较项，实时字幕另看部分结果延迟与反复改写程度。
- 无实测前不承诺延迟数值，不决定混合模型为默认；若代价/质量收益不足则使用句末模型。

### 3.2 Windows虚拟Cable端到端测试

用户授权后续由Agent自行设计并执行语音测试，Windows已有虚拟Cable。参考工程`tests/test_e2e_full.py`的设备枚举、SAPI生成WAV、指定CABLE Input回放、从CABLE Output采集的流程；不能复制原脚本的真实OSC输出、远程STT依赖或固定设备编号。

- 使用隔离的MorphForge测试副本与临时数据；测试语音只从指定Cable采集，不改变系统默认音频设备，不采集用户现实麦克风，不发送真实VRChat OSC。
- 优先使用原项目已有合适测试录音与Windows本地SAPI生成的可重复语料，不为生成测试音频额外请求云服务。
- 包含纯静音、单句、连续多句、短暂停顿、长静音、句首/尾辅音、关键词、近似但不应触发的词、partial反复改写、取消、切换输入目标与AI忙碌。
- 通过实际采集链验证VAD、识别、输入框和关键词提交；用fixture建模接收器或dry-run确认提交次数和指令，不因测试关键词启动付费建模。

- 在线测试先验证本地门控，真实在线调用限制为必要短语料并记录费用口径；密钥不进入录音、日志或报告。
- 记录识别准确性、首尾截音、P50/P95、冷/热启动与资源占用；结束后只清理自己创建的进程和设备句柄。

### 3.3 在线识别的本地 VAD 与关键词

- 麦克风音频先经本地 VAD，保留短预录缓冲避免截掉首音节，确认语音后才向在线后端提交音频；句末后提交尾部并及时结束/释放会话。
- VAD需有开始/结束迟滞、最大句长、取消与静音超时控制；具体值由实测确定，不能简单丢弃所有判为静音的帧而破坏服务端的音频时序要求。
- 需结合在线后端的实际会话/音频计费方式测量费用变化，不能只凭上传字节减少宣称节省了等量费用。
- 区分“关键词开始建模”和“关键词唤醒录音”：本次要求的是可选关键词提交建模；持续离线唤醒监听不是已确认必做项。
- 如果将来加入常驻唤醒，优先在本地检测，不能为了检测关键词长期开启云识别。

## 4. AI 修改期间默认关闭手工编辑

- AI 持有场景修改权时默认关闭手工放置、删除、拖动与属性修改，避免相互覆盖。
- 相机旋转、观察、截图、对话、语音输入和打断能力保留。
- 需要手工接管时先暂停/打断 AI，在当前事务结束的安全点移交；AI 结束或取消后恢复先前编辑状态。
- 不能只禁用按钮：修改 API 继续执行项目/版本/写入者校验。语音 partial 和查看操作不应占用几何写锁。

## 5. AI 资源感知与可发布交付

用户要求 AI 知道已用体素、Box、面数量，并交付满足256范围与Box/面限制的模型。

- 从当前目标能力读取空间、显示槽总量、Box/三角面限制、材质与后续文本槽容量。离线自由创作与 VRChat 受限交付采用明确的目标配置。
- 每次建模修改结果与场景检查向 AI 返回当前 revision、包围盒、各轴尺寸、Box数、三角面数、目标槽占用/剩余、体素占用统计及超限原因。
- “体素数量”区分 Box 体积求和与去重后占用；未执行精确去重时明确标成估算，不能把重叠体积算成精确值；斜面与三角面不冒充实心体素。
- 当前 MF6 的16384是地址容量基线，不能对 Box 和三角面分别承诺各16384；应核对实际池分配及组合容量。
- 256范围指映射后落入256³目标空间并满足每轴边界，不要求草稿所有坐标非负；使用统一原点/平移规则，不能静默裁掉越界部分。
- 在提示词中说明目标，在工具回执中反馈实际占用，在最终完成/发布入口执行硬校验；超限时必须修正或报告未完成，不能只写“已完成”。
- 不把会反复变化的资源摘要插入已发送上下文前部；通过追加的工具结果更新，保持既有前缀稳定。

### 5.1 AI 文字工具约定

- 向 AI 暴露现有体素文字能力及新增贴图文字对象能力，工具名称/参数需明确区分几何文字与贴图文字，不能共用含糊的默认分支。
- 通用的“写字/标题/标牌”请求默认生成体素文字，使用当前字体、格尺寸、挤出等几何参数，并计入 Box/体素/空间预算。
- 实时字幕、明确的贴图文字需求或显式任务设置才启用文本框路径，计入其独立字符槽/对象预算；不能为了绕过 Box 限制静默改成贴图。
- 两类工具均返回创建对象/分组、包围盒、资源占用和 revision，支持后续修改、删除及截图检查。
- 模型上下文、中文优先的工具说明、界面默认项和测试同时验证默认体素行为。

## 6. 内部观察与草稿截图

用户要求摄像机能看到内部信息，支持只拍草稿部分，或临时移开/隐藏某个范围。

- 在现有多视角/自定义相机/动画姿态截图上增加：按分组或选区隔离、临时隐藏、裁切平面/空间裁切范围，以及可选分组爆炸视图。
- 支持选择当前草稿 revision 或已提交快照作为截图来源；截图必须固定来源版本，避免异步渲染时混入新修改。
- 所有隐藏、裁切、移开只作用于本次拍摄视图，不修改真实几何、不触发OSC、不产生删除命令；成功、失败、取消均恢复观察状态。
- 截图回执标明来源、revision、可见/隐藏范围、裁切和临时偏移，防止模型把剖视图当作完整作品。
- 允许“只看正在编辑的部分”的快速观察；最终完成验收仍保留完整模型视图，不能用隐藏问题区域的截图代替整体检查。

## 7. 面板开关、VR操作与视角导航

2026-10-22补充：用户希望部分按钮作为开关，再次点击可关闭已展开页面；子窗口可通过旁边区域返回，方便实际VR操作。移动查看快捷键尽量兼容Unity。

- 适合临时查看的侧栏、工具面板和浮动窗口使用明确的开关按钮：首次打开，再次关闭，按钮高亮反映当前状态。常用面板保留输入、滚动和展开状态。
- 子窗口提供固定可见的返回/关闭按钮；适合轻量窗口时支持点击窗口外的遮罩返回，并支持Esc。不能通过点击背景静默丢弃未保存内容或取消正在执行的任务。
- 窗口外点击只负责关闭当前浮层，不能穿透为场景放置、删除或另一次按钮操作；嵌套窗口先返回上一层，不能一次关闭所有页面。
- 面向VR指针操作采用足够大的点击区域、明确的选中/悬停状态；关键操作不依赖精细拖动、悬停提示或只有键盘才能触发的快捷键。
- 视角导航以Unity习惯为目标，覆盖环绕、平移、缩放、右键飞行、速度调整和聚焦所选对象。具体组合键在实现前对照Unity导航规则及现有编辑器绑定，作为可选的Unity导航预设，提供屏幕操作提示。
- 快捷键按上下文分发：文字输入、录音热键、弹窗与场景导航不能抢占彼此；焦点位于输入框时不得把正常输入解释为相机移动或场景编辑。
- 导航输入与手工几何编辑分离：AI修改期间禁用手工编辑，仍允许相机观察；VR中有对应的按钮/手柄操作路径。
- 验收覆盖反复开关、外部点击、Esc/返回层级、输入内容保留、点击不穿透、输入焦点、拖动结束和实际VR指针操作。

## 8. 工作台布局、流式消息与相机缺陷

2026-10-22用户补充，均待下一轮实现。

### 8.1 流式文本消息

- 上游模型的正文/思考内容以消息为单位阅读，默认单行，可展开多行；两种模式之间切换保留内容和浏览位置。
- 单行时随流式文本平滑向右跟随尾部，多行时向下跟随；消息卡片有最大高度，超出后在卡片内部滚动，不能无限撑高整个页面。
- 用户主动滚动离开尾部时暂停跟随，不能被每个新事件强制拉回；提供“回到最新”并在回到尾部后恢复跟随。分别处理卡片内部滚动和消息列表滚动。
- 对大量小片段合并刷新，避免每个token创建滚动动画、闪烁或堆积；展开/折叠后正确恢复自动跟随状态。

### 8.2 输入区与设置

- 输入token展示更清晰简洁：优先显示当前上下文用量（k与百分比）和本次上游输入用量；累计计费输入/输出、来源和估算解释放详情，不能把累计输入当当前上下文。
- 保留缓存命中与告警的可观察性，但避免在输入框周围堆叠长说明。未知/未报告不显示成0；本地估算与上游实报明确区分。
- 设置页提供“严格检查append-only”开关，默认开启；关闭严格检查只改变异常时告警/阻断策略，消息构造仍保持稳定前缀，不能主动重排或改写旧历史。与缓存命中阈值/上游未报告缓存用量的策略分别说明，不能混为一个开关。
- 当前“发送方式”指`messageMode`中的插话/打断并继续/排队，移入设置；不在输入框旁长期显示下拉框。运行中应通过简短提示说明当前生效方式。
- 建模类型、目标尺寸、参考图片、消息队列等收进输入框附近的单个可折叠组件，收起时显示必要的选择摘要/队列数量，保持输入附近简洁；已有常用发送、语音和运行控制仍可方便访问。
- 语音partial结果、图片选择与折叠状态的异步更新不能抢夺输入焦点或重置正在输入的草稿。

### 8.3 左侧绘制与材质叠层

- 左侧手动绘制工具可开关，默认关闭并折叠；展开面板和启用场景编辑是两个可辨识状态，不能仅因查看面板就开始放置。
- AI编辑期间默认禁用几何手工修改，观察导航仍保留，与前述所有权规则一致。
- 视口左上角可叠层显示当前作品实际使用的材质：以紧凑缩略图/色块与名称为主，可折叠，数量较多时内部滚动；不一次展开完整贴图库。叠层避免遮挡/抢占相机操作。

### 8.4 反复适应/主视图后的缩小与移动异常

用户观察：反复点击“适应”“主视图”等后，模型越来越远、越来越小，同时移动出现异常。记录为待复现缺陷，不预先认定根因。

- 适应/主视图应依据作品和所选动画姿态的包围盒确定相机，不能在当前距离上反复乘系数；辅助网格、手柄、相机自身与材质叠层不计入作品范围。
- 核查相机position/target/zoom/投影参数、OrbitControls内部状态、近远裁面、平移速度与坐标尺度是否一致；避免旧动画或阻尼状态在按钮复位后继续漂移。
- 验收：不改作品时连续点击20次，镜头结果应在数值容差内一致；随后环绕、平移、缩放、聚焦、主视图切换仍正常。覆盖空场景、超小/大作品、偏离原点、文字对象、动画姿态、不同窗口比例和透视/正交模式。
- 带隐藏/裁切的截图取景与常规取景分开管理，不能因临时拍摄扩大包围盒或污染用户镜头。

### 8.5 右上角状态与进度

- 将运行状态、发送进度条、预计剩余时间集中在视口右上角，采用紧凑布局。
- 区分AI生成状态与OSC本机发送进度；没有可靠总工作量时显示阶段/已耗时，不能捏造生成百分比或预计完成时间。
- OSC预计时间依据待发批次、配置间隔、实际队列与重发/补播模式计算；初始发布与持续循环补播分开显示。
- 进度完成只代表本机发送完成，不把它标成所有远端已完整接收；暂停/等待通道/断开时状态和ETA同步变化。

## 9. 定位球显示/抓握分离与外部交互

用户指出之前已要求“橙色球显示”和“允许抓握移动”分开控制，当前未实现。本轮核查确认是遗漏，不计入已完成能力。

### 9.1 当前代码事实

- `PlacementInteractionBuild.cs`设置球附近ContactReceiver为`allowSelf=true`、`allowOthers=false`、`localOnly=true`。
- 公共插件生成的`MorphForge.prefab`两个接收器仍是上述配置；抓握状态机以`IsLocal`和自己的左右手势/接近参数判定。没有让陌生玩家取得定位锚点控制权的逻辑。
- 当前`Placement.controller`仍在进入抓握/结束抓握时引用`MF_Handle`；HandleOn/Off还同时控制`HandleVisual`和`Sensors`，所以隐藏球也影响抓握，并未真正拆开。源码中的“只影响显示”注释不能代替生成资源核查。
- 公共包中`MF_Handle`为本人本地参数，远端定位球隐藏；目前不是供别人抓取的世界Pickup。

### 9.2 必须补齐的独立控制

- `显示定位球`：仅改变视觉物体；不能关闭检测器、改变抓握状态或锚点位置。
- `允许本人抓握移动`：仅控制接近/手势检测与抓握状态机；关闭后球仍可保持显示。建议新增本地Bool，不增加同步位，实际位置与抓放仍走既有同步逻辑。
- 明确支持四种组合：可见可抓、可见锁定、隐藏可抓、隐藏锁定。隐藏时仍可由用户主动打开可抓，不隐式互相修改开关。
- 正在拿取时关闭允许抓握，应在当前姿态安全释放并固定，不能跳回默认位置；显示开关在拿取过程中不触发释放。
- 复位、跟随世界/人物、保持水平、缩放继续独立；明确保存/默认值，并在Unity与真实Avatar验收。

### 9.3 他人与世界交互的范围

- 当前没有开放他人移动作品，也没有通用世界物理/可站立碰撞。继续保留先前不做几何碰撞的范围，除非用户重新指定。
- 他人触碰触发动画/变色/按钮可以作为Contacts扩展方向，需本人显式授权、事件过滤、去抖与权限处理；不能仅打开allowOthers就声称支持抓取。
- 真正“别人握住球拖动整个作品”需独立验证PhysBone抓取或其他锚点约束方案、控制归属和所有观察者一致性。Contact触发本身不提供任意外部玩家手的完整位置/朝向引用。不能直接复用只绑定本人左右手的约束当作已实现。
- 世界交互可研究世界中显式放置的兼容Contact信号→Avatar参数→动画状态；不得假定任意旧世界的普通碰撞体都能驱动我们的作品，也不能把Avatar上的物体自动当作可由Udon接管的VRC_Pickup。
- 现有官方Contact文档涉及世界与Avatar交互，实施前必须核对本项目SDK3.10.5和客户端版本的支持方式；世界Contact、PhysBone抓握与普通物理碰撞分别验证。参考：https://creators.vrchat.com/avatars/avatar-dynamics/contacts/ 。
- 默认不开放他人操作；若后续实现，作为独立权限选项，不能借用显示球或允许本人抓握的开关。

## 10. Mini模式与语音悬浮窗

用户新增：程序UI提供mini模式，仅显示所需界面，可选置顶；语音需实用悬浮窗，参考旧工程并完善交互。

- Mini预设至少包括“语音识别与文字同步”“AI建模进度”，允许选择显示项目；完整模式与mini可快速切换，保持工程、会话、录音与OSC任务连续。
- Mini/悬浮窗是同一Rust服务的轻量视图，不能启动第二份识别、模型请求或OSC发送器；关闭某个视图与停止任务分开定义并在界面提示。
- 可选窗口置顶，支持拖动、调整尺寸、透明度、收起/展开、返回主界面；保存位置和大小，处理多显示器/DPI及屏幕断开后窗口找回。
- 语音悬浮窗显示录音/VAD/识别/发送状态、音量、临时文本、最终句子和必要错误；提供开始/停止、取消、修正文字、重发、清空，以及目标（文本框/建模输入）和同步开关。识别重试与再次发送不能产生重复建模或重复追加。
- AI进度mini显示当前阶段、简短流式内容、资源占用、发送进度/可用ETA，保留暂停/继续/停止/展开查看；未知进度不伪造百分比。
- 操作控件有足够大的点击区域；拖动区域与按钮/文字选择区分，避免旧项目“任意mousedown即拖窗”影响输入和点击。自动高度有上下限，长文本内部滚动，不能无限增高。
- 录音状态始终清晰，窗口隐藏或切换mini不能意外开始/结束录音；选择新目标时遵循当前语音session目标固定规则。
- 当前主窗口最小900×600，mini需要独立窗口/窗口尺寸策略及原生控制接口，不能仅靠CSS隐藏主页面。保留当前远端HTTP页面不具备通用Tauri IPC的边界，不能为置顶放开任意网页原生调用权限。
- 参考源码：`src-ui/src/overlay.tsx`已有桌面置顶透明悬浮窗、音量/partial/final状态；`crates/vr-hud`已有独立SteamVR/OpenVR伴随进程和IPC。参考工程为Tauri v1，不直接照搬到当前v2。
- 桌面置顶不能当作VR头显可见的保证；实际VR需单独评估/适配已有SteamVR overlay路径，不能用桌面窗口验收代替头显验收。
- 测试覆盖小窗按钮、焦点、文本修正、DPI/窗口位置、主窗口关闭/重开、重连、录音与发布任务连续性，验证无重复工作进程或重复发送。

## 11. Avatar本人可见的头边预览与前方朝向

### 11.1 可选头边预览界面

用户要求可在头部边缘选择位置（含边角），仅自己看见，观察模型结构和文字结果，尽量不增加同步参数。此项为待原型验证的功能方向。

- 菜单提供本地开关、左/右/左上/右上/左下/右下等位置预设、偏移、显示尺寸和取景缩放；默认关闭。
- 使用已有IsLocal以及不同步的配置参数控制本人可见，不增加同步bit；“无新增同步参数”不等于完全没有本地参数或GPU成本。
- 优先评估Avatar内Camera→RenderTexture→头边显示面板：额外视角拍摄已接收的实际模型/文字，不复制OSC流，也不复制16K粒子状态。可复用字库/材质，RenderTexture与额外绘制有独立成本。
- 核实SDK相机白名单、目标纹理、相机启停、取景隔离、镜面和相机递归；官方参考：https://creators.vrchat.com/avatars/whitelisted-avatar-components/ 。相机不带RenderTexture时有不同限制，不能按普通世界Camera假定。
- 通过头部约束定位面板并处理第一人称头部隐藏；验证左右眼视差、舒适距离、遮挡、画面朝向及不同Avatar身高，避免贴在眼睛附近导致不适。
- 首轮比较低分辨率/低刷新率与按需开启，提供正面/斜视取景或缩放选项；默认预览Avatar真正已绘制结果，不能用外部草稿冒充客户端接收完整性。
- 测试其他玩家不可见、相机和面板远端停用、镜子/拍照行为、文字清晰度、双面可读、材质透明与完整模型取景。
- 若Avatar相机方案效果或成本不合适，评估额外Shader视图或外部SteamVR预览；不得在未实现前声称单一粒子Renderer可直接共享第二套渲染位置。外部预览不等于Avatar实际状态。

### 11.2 前方放置默认面向本人

用户观察移动到本人前面时作品正面仍朝Avatar前方，要求改为作品与Avatar面对面。

- 初始前方停靠、复位/移动到面前时，默认相对Avatar水平朝向绕Y旋转180°，使作品正面朝本人；不能用负缩放镜像替代。
- 作用于作品定位锚点，不修改草稿自身坐标/字形/材质UV；编辑器主视图、Avatar预览与作品“正面”的定义需统一。
- 不在每帧持续强制作品看向本人：抓握或放到世界后继续保留用户摆放的姿态。
- 不静默翻转用户正在摆放的现有作品；明确重置/前方停靠动作的行为。世界固定、跟随、水平保持、缩放和隐藏/可抓开关继续独立。
- 验收包含体素建筑、三角面、非对称字母/中日英文本以及双面字，确认不是通过镜像或背面补字掩盖定位错误。

## 12. 后续顺序与验收重点

1. 完成动画方向讨论，再冻结文本/动画对象数据模型和协议扩展。
2. 验证按位字库、半全宽混排、默认文本框和实时文字最新状态路径。
3. 接入公共语音服务、两处输入框；验证在线前置本地 VAD、关键词提交、取消、目标固定、partial/final去重；实测混合识别与单句离线识别，按时延/质量选择默认。
4. 完善AI写入所有权、资源回执和最终目标校验。
5. 增加隔离/裁切/临时移开截图，验证异常恢复和场景内容不变。
6. 调整流式消息、输入区、设置与视口叠层；修复适应/主视图重复点击的相机漂移，补充滚动与导航回归。
7. 补齐定位球显示与允许抓握的独立控制及前方面对本人；他人和世界交互仅先评估，未经原型验证不列为可用能力。
8. 实现mini模式与语音悬浮窗，验证共用任务状态、置顶和VR显示边界；对Avatar头边本人预览先做相机/渲染/舒适性原型。
