## B：持久文本对象与二值字库（0.18.0开发）

- 官方GNU Unifont 18.0.01 HEX与JP BDF转换为BMP定址R8打包字库。每套2,097,152字节位图+65,536字节宽度表，57,086字形；两套4.125MiB像素/宽度载荷，不是Avatar下载增量。转换脚本、内容哈希、版权与OFL许可随源码保留。
- 文本框进入Scene事务，参与保存/重开、撤销/重做、清空/分组删除、保护分组、整体平移、范围及容量检查。AI新增text_panels工具，体素文字仍为默认。
- Rust排版实现半全宽、NFC、自动换行、英文短词整体换行、常见标点避头尾、对齐、裁切/保留末尾/缩小。BMP外字符显示缺字并在回执列出。
- 编辑器增加文本框模式、输入与即时预览、精确变换和方向按钮、平面拖动；字形Shader使用同一字库，正反面同时翻转布局坐标，背面整行与每字均正常可读。
- 浏览器8项通过，包含真实字体Shader、输入应用、撤销、方向按钮、正反面截图像素对比与无JS/GPU错误。见stage-b-browser。
- Avatar接收尚待阶段E实现，旧Avatar发布文本框会明确拒绝，避免静默丢失文字。尚未将本阶段安装到用户主程序。

### C/D实测记录（2026-10-22）

0.19.0冻结输入构建完成。Rust语音HTTP5项通过，包含后台离线回调正确进入现有Tokio运行时。Windows CPAL最初遇到Cable设备的非f32格式，已支持标准整数/浮点格式并实际采集验证。识别取消/停止幂等；AI持有编辑权时字幕保留在语音草稿，明确提示暂停后应用，不直接修改建模中的Scene。

实际Cable测试38项通过，完整证据stage-c-speech/validation.json。3条共同中文SAPI语料中，两种离线方案标点归一化CER均0；离线句末接收端估计约499～506ms，混合约497～503ms，其中VAD等待450ms，SenseVoice推理约46～56ms。播放端估计末音到可见final约1.0～1.07秒，包含Cable输出缓冲及轮询，不能作为纯推理时延。冷加载离线约1.81秒、混合约2.53秒。小样本未显示混合能加快最终提交，默认保留offline；hybrid提供临时文字，首次partial相对回放开始约1.52～1.55秒（含前导/缓冲）。报告中的preferredBySmallCohort仅是旧脚本的中间结果启发式，不用于选择默认值，不把3条中文语料扩展为多语言/噪声覆盖结论。

真实关键词触发仅提交一次本地fixture模型，“不要开始建模”不触发；最终字幕更新指定文本对象，轮询不重复修改。静音2秒零云连接。腾讯真实短句识别一次成功，上传音频2.892秒、1会话，未查询账单，不推断实际扣费。测试没有使用真实大模型或发送VRChat OSC，不改默认声卡。

Unity原型的Renderer属性保持方案实测失败：无论省略或补齐当前页零曲线，WD Off Direct树离开写入页后仍产生增长反馈。已切换为ParameterDriver写本地Float字节缓存、WD On树读取，并按字符页门控。首次16对象/128槽模板含5030个本地参数，Unity/VRCFury合并进入Play Mode耗时数分钟且Pipeline持续不响应，因此将首版目标收紧到4对象/128槽，并把输出层与写缓存层分离，避免复制大的输出树到每个写状态。作者侧可保存更多对象，超Avatar容量会明确拒绝发布，不裁掉内容。本地参数不等于同步bit。

恢复了仅本轮占用的Unity测试实例，恢复前场景已保存且没有用户未保存编辑；不上传Avatar、不启动真实VRChat。4对象接收器、静态截图、CPU/内存与SDK预算仍待重新验收。不能引用之前失败的text-receiver-play.json为成功证据，也不能把Unity YAML体积当运行时CPU或下载开销。


### E1接收器已通过（尚未最终安装/发布）

最终文字接收使用本地字节参数缓存，非Renderer属性“记忆”。4对象×128槽（换行占槽），12字持久页、14字短窗，所有消息共享现有240bit写入器。两层/对象：持续的按页门控输出、仅处理新消息的写缓存状态机；共8层。输出使用已验证可大于1的未归一化Direct权重乘常量，包含恒定零基准，修复删除、黑色、不透明度归零和低字节0残留。快照按Stage退出采样状态，避免空Clip退出时间导致相同Ctl内容更新迟滞。

实际UDP9012→合并Avatar Animator→Renderer属性15项通过，含跨页保持、空闲保持、独立字形与计数、短窗、无误写方块、删除、旧代次字幕拒绝、归零、同控制字再次更新。文本框代次占原Ctl中未使用的2bit，4槽占2bit，不增加同步位；保留删除墓碑参与补播。2bit会回绕，不是可靠网络ACK。旧Avatar无本机能力确认不会往9000发送文本扩展。

正面/背面实际GPU截图两对象均逐像素一致（差异0），覆盖汉字、假名、英文和多行。图片与报告在stage-e-text。当前controller约5.29MB YAML、1177 Clip、原始运行时对象内存估计8.07MB（不等于最终包/合并内存）；字体像素/宽度载荷约4.125MiB。

相同CJK填充条件的Editor Animators.Update诊断：原1D输出满512槽约11.75～11.87ms，Raw Direct+固定零基准约6.66～6.75ms；已接收28槽约2.82～2.95ms，全部文字页关闭约2.51～2.61ms。包含整个Avatar和Editor噪声，不能冒充真实VRChat成本或承诺硬件帧率。使用正反顺序六阶段采样，保留before/after原始报告。

桌面VRC页补独立allowGrab开关；字幕预设采用tail/bottom，避免连续语音填满框后停留在开头。Mini补透明度、紧凑布局、进度视图共同错误显示，未知发送进度不伪造0%；文字应用/建模按钮阻止重复提交。彩色文字浏览器Shader补标准输出色彩转换。

导出贴图文字采用二值字形的横向像素轮廓面，前后各一份正常阅读布局，不依赖自定义字库Shader；GLB使用unlit材质，OBJ/PLY/STL保留可表达的表面信息，遵守总500,000面限制。这是静态轮廓导出，原文与排版仍以MorphForge项目保存。
