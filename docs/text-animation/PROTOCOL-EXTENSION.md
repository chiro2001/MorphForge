# MF6文字与动画扩展接收草案

2026-10-22，阶段E实现前草案，字段需通过接收器原型冻结。继续使用现有29数据Int+Ctl，共240bit，不新增同步参数；旧Avatar不声明能力时拒绝发送新对象。

- 保留普通几何格式1..15；为format=0增加带标记扩展。普通Idle(D全零)不应清空文字或改变扩展状态。
- 持久命令：Ctl继续seq高4bit/format低4bit；D28=254作为扩展标记，D0为操作码，其余字段承载文本配置、字形页、删除、动画定义/状态等。global接收器仅在该标记时接纳format0，复用已有锁存和节拍，防止数据在读写期间被覆盖。
- 候选字形页：D0=写页，D1=文本槽，D2=页号，D3=长度/标志，D4..27为12个16bit字形；外部完成分行后插入换行码，避免Shader重做复杂断行。最终容量先以16文本对象、每对象128槽评估。
- 实时14字窗口：Ctl=(文本槽<<4)|0，不使用事件序号；D0..27为14个16bit字形，D28=128+字符数(0..14)。直接参数驱动字形缓存，内容更新不依赖Ctl翻转。位置/字号/颜色由先前配置或默认值提供，单次快照只更新内容。
- 快照模式必须与全零Idle和D28=254的命令严格区分。快照不推进普通几何命令序号；普通解码器不锁存快照，避免16序号回绕造成几何首帧被误跳过。
- Avatar按地址缓存显示值，退出快照模式后保持文字，不把后续几何载荷当字符。外部只保留每个实时窗口的最新待发版本，并在唯一OSC发送队列调度，不由语音线程另开UDP发送器。
- 持久文本和配置参与补播/晚加入恢复。实时快照提供的是当前窗口，不等于所有旧文字或定位配置已可靠恢复。
- 字形位图为已上传的中/日R8按位字库；网络只传字形编号和控制数据，不传PNG。
- 多人网络不能保证每个中间字符都显示；验证目标分别为本机无解码覆盖、远端最终状态收敛、补播后完整恢复。

动画仍需要解决groupId持久存储和播放时钟；不能直接占用当前颜色、形状等字段，也不能将普通_Time当作跨客户端共同时间。


## 原型验证修正

Region8现有format0/D28=168..175并非空闲；接收端路由已增加范围保护。持久文本扩展为D28=254，op1配置、op2字符页、op3样式、op4删除；每页12个UTF-16 BMP码点，外部排版插入显式换行。128是包含换行的字符槽数。

2026-10-22实际UDP测试表明，Write Defaults Off + Direct BlendTree不能作为可靠的Renderer属性存储：离开页状态后出现累加反馈，省略零曲线会加剧问题。因此切换为本地Float字节缓存，由ParameterDriver按页写入；输出树Write Defaults On且按字符页门控，仅有内容的页参与求值。缓存不添加同步参数。不能再把“空状态保留Renderer属性”作为实现原理或完成结论。此修正正在Unity验证。


首版容量收紧为4对象×128字符槽（含换行）。16对象原型在Unity/VRCFury合并阶段开销过大，未发布；不能沿用前文候选容量作为最终承诺。控制地址字段仍可表达16槽，以便后续能力协商扩容，但发送端会按当前4对象容量拒绝越界。
