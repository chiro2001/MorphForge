# MF5：微缩、实时材质与双粒子池

MF5 接续 MF4 的无面捕主档：240 bit 几何 + 14 bit 定位，总计254 bit。本体衣装/道具参数继续本地使用。目标是让新颜色和常用表面外观随绘制实时发送，减少重传头像；新图片仍要打包到头像。

## 缩放与升级

持久化及 HTTP API 的 `scale` 仍是物理倍数，避免旧作品尺寸改变。界面采用新基准：`显示百分数 = scale / 0.05 × 100`。

| 新界面 | 实际 scale | 单格边长 |
|---|---:|---:|
| 1% | 0.0005 | 0.125 mm |
| 10% | 0.005 | 1.25 mm |
| 100% | 0.05 | 12.5 mm |
| 1000% | 0.5 | 125 mm |

逻辑空间不变，为256³；最大单轴作品可从3.2厘米到32米。实际显示大小取决于占用格数。旧scale=.05升级后显示100%，没有改写成1。MF4等旧头像仍使用旧线性缩放，软件保留兼容入口，不能把MF5的缩放编码发给旧头像。

`MF_Scale` 使用有符号float的全范围：`wire = 2 log₁₀(scale/.0005)/3 - 1`。Avatar采用25个对数采样的BlendTree节点。网络float量化和节点间线性插值会造成小幅尺寸偏差，界面百分数不是测量级精度。头像菜单提供两轴控件及1/10/100/1000%四档预设；临时菜单参数仅本地，不新增同步位。定位球视觉温和缩放，抓取传感器半径保持可操作。

## 网络布局

三个网络lane，各 `MF5_L{0..2}_D00..08` 九个Int以及一个 `Ctl` Int，共80bit/路。参数仍为Int，单个Int占8bit。定位参数14bit沿用，只有MF_Scale语义改变。所有几何与外观字段和Ctl在同一OSC bundle发送。

| 字段 | 单长方体 | 双单位体素 |
|---|---|---|
| D00..02 / 24bit | 最小坐标XYZ | 主池位置XYZ |
| D03..05 / 24bit | XYZ长度减1 | 次池位置XYZ |
| D06..08 / 24bit | 表面载荷 | 共享表面载荷 |
| Ctl高3bit | 每路独立序号0..7 | 同左 |
| Ctl低5bit | 操作码 | 同左 |

X/Z线坐标加128，Y不偏移；源数据保留有符号坐标，范围X/Z -128..127，Y 0..255，长方体必须完整落在范围内。源作品超界时发布预检阻止，或先整体落地居中；传输层不偷偷裁剪作品。

| Opcode | 操作 |
|---:|---|
| 0 | 不执行 |
| 1..8 | 主池绘制，表面mode=opcode−1 |
| 9..16 | 次池绘制，表面mode=opcode−9 |
| 17..19 | 两块单位体素，mode=opcode−17（目录/RGB/PBR） |
| 20 / 21 | 主/次池精确删除 |
| 22 | 本路两池清空 |
| 23 / 24 | 主/次池区域擦除 |

每路有两个独立Store，每池2731，总物理容量16386，软件限制16384。队列记录几何到六个池的归属，删除和替换发回对应池。配对要求主/次池各一块单位体素且最终线外观一致；程序纹理及贴图染色先使用单Box路径。

不能把两个出生泵接到同一个Store：原型验证出现重复/漏块，已改成两个独立池，协议能力标记为 `mf5-dual-pool/1`。不要复用早期共享Store原型的opcode和能力标记。

0.25秒间隔时每批最多三个长方体或六块可配对单位体素：理论12 Box/s或24 voxel/s。5000条分别约417/209秒，16384条分别约1366/683秒，不含清空、擦除、排队及网络损耗。长方体仍可表示大量格子，耗时按Box数和可配对情况计算。未承诺网络可靠送达；没有远端ACK，多人仍须验收。0.25秒是发送间隔，低帧率或卡顿时仍可能丢命令。

MF5周期刷新和“保留显示补播”按原六池归属重写整个目标，不做全局clear；接收端绘制会先精确删除同位置/尺寸再出生，因而可重复执行。局部重写可能短暂变化，不能宣称绝对无闪烁。新版本编辑优先于维护补播，会取消当前补播。手动“清空并重建”仍会两次clear，用于修复漏删残留和恢复未知状态。补播可帮助后加入玩家逐步收到作品，但不是远端ACK，也不能保证一次完成。

## 每块表面描述

粒子出生Color32的RGB存D06..08，Alpha存 `255−mode`。Alpha是数据，不是可见透明度；生产Shader先解码，再决定透明pass。

| Mode | 24bit载荷 | 用途及量化 |
|---:|---|---|
| 0 | style12 + tint6 + motion6 | 已烘焙目录；透明目录材质motion可作六面遮罩 |
| 1 | RGB888 | 精确24bit sRGB，不透明哑光 |
| 2 | RGB565 + metallic2 + roughness2 + transparency2 + emission2 | 颜色565；表面各4档，发光0..3 |
| 3..6 | RGB444 + rough2 + transparency2 + emission2 + noiseScale3 + seed3 | 程序水、云、木、石；比例8档，种子8档 |
| 7 | 内置style12 + RGB444 | 复用内置图像，实时染色 |

程序水金属度固定.2，其余程序材质0。原始艺术材质保留，VRC预览展示解码后的 `vrcEffective` / `vrcColor`。不同GPU的噪声hash可能有细微纹理差异。水云有动画，木石和纯色静态。

实时材质没有额外六面遮罩空间，目前不隐藏其内部透明面；目录透明材质保留既有遮面。VRC仍是粒子透明排序近似，不能保证交叠水云和真实体积渲染等价。新PNG/任意像素不走OSC生成纹理：必须重新打包，或选内置贴图/程序纹理近似。

作品逻辑材质ID可到65535，烘焙style仍至4095。贴图按UID与渲染内容匹配，允许作品间ID不同；UID相同但图片不同不会静默替换。运行时色板即使与烘焙style编号相撞，也优先发送自己的颜色描述。

## 内置方块工坊

原 `pixel-workshop` 19种保持兼容；新 `block-workshop` 48种原创MIT像素方块，包括木材、石砖、矿物、玻璃、羊毛、陶土等。它们是Minecraft风格原创素材，不含Mojang原版资源。

MF5配套目录共76项（24基础+48像素+4历史色板），Texture2DArray为306层，metadata保持256×64。新作品经“内置方块工坊”加入材质后可直接映射到配套头像，不依赖分配的作品ID。

## 编辑器与Harness

- 实时材质对话框直接调用 `define_materials`，显示VRC量化结果；一次1..32项、revision保护、原子提交、相同定义复用。
- `define_palette` 继续可用，MF5无需重新上传头像；`builtin_materials` 可选择48种或原19种主题。
- 工具schema升级为3.7；旧会话必须显式升级工具说明或新开上下文，不能为新工具自动重写历史前缀。
- 同一表面设置的无贴图纯色按实例颜色合批，避免5000个颜色产生5000个draw call；程序材质与不同纹理保留独立批次。
- 微缩预览/透视和正交截图按真实尺度取景，降低near和最小fit跨度；截图继续使用超采样。
- 桌面Preview使用不可变版本目录，保留验收版、作品数据与正在运行的旧版本。新目录通过pending文件在下一次启动迁移，连接默认关闭。
