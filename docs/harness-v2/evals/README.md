# Harness v2 实际模型评测

所有测试使用隔离数据目录和 loopback 后端，OSC 保持禁用。真实 API 的原始响应、工具请求与结果由后端日志保存；本目录保留评测输入、报告、完整事件副本和可审阅的截图。测试脚本不读取或输出凭证。

## R0：0.1.0 基线

- 代码：`abc639c`，冻结为独立二进制；中文任务“云港信使驿站”。
- 模型：`deepseek-flash`，reasoning=`high`，每响应输出上限16,384。
- 结果：155秒，3个完整模型步骤，256 Box，7种材质，5个分组。创建了大形并截图，但后续响应未完成，**未 commit、未保存作品库**。
- 原始错误：`response.incomplete`，`reason=max_output_tokens`；该响应的16,384输出token全部为reasoning token，没有完整工具调用。已完成几何保留，没有执行半套工具参数。
- 图像审阅：主楼和塔楼剪影、阶梯蓝屋顶与有间隙的连接桥可见；主楼仍是大块白墙，缺少可辨认的钟面、拱门、发光窗和云底。该图仅为大形阶段，不能算完成作品。
- 用例自身也有问题：“0..255所有坐标”与VRC的X/Z编码范围冲突。R1将坐标提示修正为X/Z `[-128,128)`、Y `[0,256)`；R0使用负X/Z不能判为模型错误。

## 后续实验的变化

R1同时引入中文system/tools v2、短规划与分阶段生成约束、有界incomplete恢复，并使用reasoning=`low`。它是工程迭代评测，**不是只改变一个提示词变量的A/B实验**。有界恢复不会执行不完整工具，不会静默提高用户的输出上限；重试消耗仍计入运行预算。

R2在已有作品上检查真实体素中文标牌、插话、打断续接与compact。对既有五个分组进行Box多重集合比较，避免“画面看起来类似”掩盖丢失几何。消息的accepted ACK与applied事件分别记录，重复请求必须重放同一ACK。图像质量、交互正确性和任务是否真正保存分别给出结论。

以下各轮均已实际运行并检查图像；输入、失败、恢复和最终通过分别记录，不把接续收尾算作一次自动完成。

## R1：中文v2与低推理强度

- 结果：157秒、8个完整响应、687 Box、15种材质、6个分组。完成3次成功截图、2次真实图后修改，未出现incomplete；仍因累计预算240,000耗尽而失败（实际记账247,995），没有commit或入库。
- 第一段Recipe算出零尺寸，只有泛化的`size must be positive`错误；模型自行修正后继续。下一版错误补充具体操作、坐标、尺寸和分组，并要求跳过空盒。
- 图像审阅：相对R0已补出钟面、拱形入口、窗框、廊柱、路面及铜色细节；云岛仍偏薄，悬挂浮台和主体之间较疏，作品仍有收尾空间。不能把“有截图、有修正”写成“完成”。
- 原任务要求VRC，但当前最低Y为-14，不能直接发布。独立艺术空间允许该几何；R2以保留既有Box的交互回归为目的，明确不发布VRC，坐标兼容性另测。
- 精确用量：首轮输出10,993，其中reasoning为10,944；第5轮输出12,247，其中reasoning为9,231。输入从4,321增长到45,264；每组3图约增加2.8k–3.6k，累计推理/代码历史的重复输入是主要增长来源。

R1→R2具体调整：system升为2.1，提供每步剩余Token/步骤/活跃时间；要求阶段commit、临近预算停止细化并入库；Recipe错误可定位；compact阈值从60k改32k。R2显式预算450k，不能把这次提高上限归因于纯提示词收益；原始reasoning链保留，不通过删协议项省Token。

## R2：交互、字体与compact

- 98秒、18步骤、420,001 Token，完成了同run插话/打断接续、两次compact、真字体文字、灯具修正、commit和作品保存；739 Box。
- 几何比较仍判**失败**：新牌匾底板/边框覆盖了8个既有`building` Box，拆分/删除了部分墙面与装饰。模型最终口头声称“全部旧Box未移动”，不能作为保护成功证据。其余4个受检组严格保留。
- 两次`PREVIEW_CONFLICT`均正确拒绝：第一次模型在preview后改变origin/align/group，第二次preview遗漏group，apply才指定sign。第三次完整预览才成功。
- 入库首次把视角名`hero/front/top`当成artifact而失败；随后省略views保存成功，但作品没有缩略图，不能算完整浏览体验。
- 字号8产生了真实Box，但中文细节过少。R2b明确使用至少16号，先完整预览并直接复用applyTemplate。

R2→R2b：Project增加用户控制的保护分组硬约束，覆盖事务必须整体拒绝；模型收到准确冲突后移动新增内容。文字preview提供完整applyTemplate，保存作品自动复用当前revision最近一次成功capture的真实图片。system/tools版本升到2.2。

R2b在新隔离目录恢复R1原始687 Box和首次compact前的原始Conversation，不把R2受损场景作为新基准，也不修改或覆盖R2失败证据。输入来源在`r2b-protected/input-provenance.json`中登记。

## R2b：硬保护与调用模板

- 192秒、13完整步骤、393,737 / 450,000真实Token，766 Box。五个既有分组严格全部保留；16号字体标牌和铜灯完成，插话/打断/compact与检查点提交通过，工具调用没有错误。
- 整体仍判失败：最终只差入库，但估算预检把实际约28k的输入估成62k，在真实余额56k时提前拒绝下一次模型调用。任务没有保存成作品，不能写成全通过。
- 此问题来自本项目2.1新增的预算预检，不归咎于模型或API。后续取消估算硬拒绝，按真实usage做累计门限；本来无法预知下一请求的完整输入成本，阈值允许最多一个响应的不可预测溢出。
- 2.3增加`finish_artwork`显式终态动作：将最终commit、图片关联入库与完成摘要一次处理，避免再花一个完整请求仅产生结束语。成功与取消/失败必须继续遵守工具配对与提交守卫。

R2c直接接续R2b已提交的安全检查点，只复核并收尾，锁住全部八组；不会重做或覆盖本轮场景和失败证据。R3另开空场景检验完整普通创作及VRC坐标范围。

## R3 / R3c：空场景创作及连续修字

R3从空场景搭出745 Box的灯塔、岛、水面、拱廊、桥和字牌，全部坐标合规并完成阶段commit，但仍判失败：出现可恢复的尺寸/语法/预览指纹错误，模型把字放在木牌背后，18步骤后实际369,315 Token超过350k门限，尚未入库。该轮没有一次提示自动完成。

R3c根据真实正面截图发出明确接续指令：锁定原七组、按+Z正面关系增加`sign_front`，旧背字暂不删除、不重建场景。5步骤、110,828 Token、21.7秒，完成真正字体Box文字、复核和`finish_artwork`，791 Box、全部VRC坐标合规、真实三视图入库；全部检查通过。旧背字被保留是显式无损修正要求，模型摘要也披露了这一点。

这组验证证明连续指导、硬保护、字体、视觉反馈与收尾能够闭环，不证明模型不存在空间判断错误。照片与完整失败记录保留，后续可据此继续优化贴字定位和提示词。
