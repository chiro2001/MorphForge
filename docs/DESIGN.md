# MorphForge设计基线

> 2026-10-19 新确认的权威方案见 [plan/README.md](plan/README.md)。本文保留Stage1–3历史设计。当前目标已扩展为独立体素工作台，VRC是可选适配器；面捕固定161bit，MF3主档56bit。

更新：2026-10-19。本文为历史统一设计记录；早期v1/A/B等为讨论历史，不代表已有实现。实际证据见 [验证文档](VALIDATION.md)。

下文记录的历史实现版本为[Stage3：底部中心定位球](stage3/README.md)，配套[浏览器手动编辑器](editor/README.md)；接收核心沿用[Stage2：MF2单次提交与盒体UV](stage2/README.md)。Stage1保留为旧双阶段协议及历史客户端对照；MF2需重新上传对应Avatar后使用。

## 目标与范围

标准PC/PCVR Avatar携带可逐步修改的视觉体素/长方体场景。外部程序通过OSC参数输入，预上传Animator、原生粒子与Shader接收并保留显示。首阶段不接AI、不上传Avatar、不启动真实VRChat，也不承诺多人可靠性、世界碰撞或Quest兼容。

## 设计决策

- 模型在外部Draft稀疏体素空间快速编辑与截图；Publish冻结指定对象快照并更新Published权威目标。
- 唯一OSC写入者异步发送发布任务和周期刷新；模型不持锁等待网络。
- 提交是权威目标，已发送/本机应用/远端应用分别记状态。后端按版本合并未开始任务，发送不读取可变草稿。
- Published可编译为相同完整描述的连续长方体，减少命令与粒子。单位体素是size=1³的盒体。
- 粒子保存位置、出生尺寸和元数据；原生速度为0。Shader负责格纹理/材质解释及后续运动，避免每个体素生成Animator层。
- 256³逻辑格，h=0.25m，Stage3采用底部中心锚点：X/Z格中心=(g+0.5-128)h，Y格中心=(g+0.5)h，再乘内容缩放。范围每轴64m，实际容量独立，当前64粒子。Stage1/2仍为三轴中心锚点。
- 必传静态朝向取消；需要的面方向作为预上传样式变体。

## 传输设计

源参数采用Int，Animator内部工作参数可通过Parameter Driver Copy变成Float并锁存；工作参数不进入Expression Parameters。使用者可配置通道数量，但配置/分片机制尚待定稿。

当前MF2控制头为1个Int：opcode3、seq5，`Ctl=(seq<<3)|opcode`，序号0–31。旧MF1使用opcode3、准备/执行1、seq4。版本以参数命名空间和构建清单区分；目标ID随具体API。8bit头只覆盖完整命令模式，不自动解决分片、快照完整性或迟到旧场景。

0.2s是测试保持窗口候选，不是本机OSC限制或远端保证。旧MF1以0.25s准备+0.25s执行经用户现场观察正常，0.2s双阶段曾出现阶梯缺失。当前MF2只发一次完整提交，本地擦除、发射各步骤不占额外网络周期；其Editor速率结果见Stage2证据，不能替代新版远端同步结论。

### 当前MF2接收路径

外部单个OSC bundle写`MF2_D00..09`和`MF2_Ctl`。新序号进入一条本地待执行槽Q，空闲执行器将Q复制到独立工作缓存W，再运行粒子生命周期。Q满时不覆盖其中内容，但持续过载时原始源参数里的未接收中间命令仍可能被后续提交替换；没有对外ACK或无限队列。

控制器固定3层、40个Clip；待执行槽、工作缓存和计数器均为本地Animator参数。仍为11个同步Int新增88bit，当前NDMF产物总177bit、剩79bit。高层SetBox/EraseBox/RemoveBox/ClearScene及10槽载荷语义不变，原阶段位用于扩展序号。

本地流程为Latch→Settle→Erase→Release→Fire（绘制）→Done。Settle保留0.03s覆盖测试环境下的动画/碰撞器更新等待，其余阶段按动画求值推进；完整配置时长约0.035s。Editor实际观测接收锁存到完成约0.049–0.079s，受帧率影响，不是VRChat客户端保证。

Cube预烘焙面UV和面轴，粒子UV/UV2/SizeXYZ流向Shader提供每面坐标和保留尺寸；按格边长计算重复次数。纹理和示例面明暗不再用世界位置/世界法线选择投影，因此随盒体平移、旋转和缩放保持固定。修复不新增OSC字段；旧世界坐标Shader保留用于负对照。

首阶段可使用专用测试命名空间，避免未定稿控制字段与未来生产协议混淆；所有偏离必须在验证文档登记。根据实际NDMF参数合并报告计算新增同步成本；不依赖历史89bit永远不变。

### 第一阶段实际接收器

预上传资源为`Stage1/Display.prefab`、固定立方体Mesh、材质与FX；没有Avatar自定义运行时接收脚本。Editor测试观察器只负责打开GM原生OSC、读取结果和生成参考图。

链路：外部Python UDP → Gesture Manager原生OSC → 同步Int源参数 → 原生Parameter Driver锁存Float工作参数 → Direct BlendTree设置出生属性 → 原生粒子子发射器 → Shader显示。真实VRChat客户端仍待测。

| 参数 | 数量/同步成本 | 当前含义 |
| --- | --- | --- |
| `MF1_Ctl` | 1 Int / 8bit | `opcode + (phase << 3) + (seq << 4)` |
| `MF1_D00..02` | 3 Int / 24bit | min XYZ，各0–255 |
| `MF1_D03..05` | 3 Int / 24bit | size XYZ减一，各0–255，表示1–256格 |
| `MF1_D06..07` | 2 Int / 16bit | 样式低6位/高6位，共4096种码 |
| `MF1_D08` | 1 Int / 8bit | 染色码0–63 |
| `MF1_D09` | 1 Int / 8bit | 运动组/相位预留码0–63；本轮只保存，不产生运动 |
| `MF1_W00..09`及本地状态 | 不进入Expression Parameters | Float工作缓存、LastSeq、Busy等 |

共11个同步Int，新增88bit；即使部分字段只用6位，当前仍按完整Int计费。NDMF合并后本测试Avatar总177bit、剩79bit。通道缩减与分片尚未实现，不能直接称为适配任意面捕预算。

`phase=0`准备，`phase=1`执行；`seq=0..15`轮换。当前发射脚本默认准备0.25s、执行0.6s，并重复发送同一状态；此值用于功能验收，不是多人可达速度。LastSeq只抑制最近一条序号的重放，不是可靠传输、版本检查或完整快照校验。

FX只有2层：完整基向量Direct BlendTree数据层（WD On，禁用权重归一化），生命周期控制层（WD Off）。每个数据叶Clip显式绑定全部数据属性，避免分轴层覆盖其他轴。共39个Clip，控制状态数固定，不随粒子数增加；还没有CPU性能基准。

执行状态为Latch → Settle → Erase → Release → Fire（仅SetBox）→ Done。本地步骤不各占一个OSC网络时隙；Busy期间不接收下一条，发送器当前以保守保持时间串行发送，没有接收确认。

`Store`使用普通模式、无限出生寿命、零速度、固定模块根作为Custom simulation space。`Pump`只出生一个短寿命粒子，Birth子发射器指向同级Store；只切换Pump的GameObject，避免Stop/Clear连带清掉旧子粒子。RGBA按每路64级保留样式、染色和预留运动码，A不是透明度。Mesh渲染器必须使用Local对齐，关闭`applyActiveColorSpace`：默认View会让盒体面朝相机，默认颜色空间转换会破坏低值数据码。

## API语义

| API | 目标 |
| --- | --- |
| SetVoxel / SetBox | 位置、尺寸、样式等完整描述；本轮测试操作码1，中心点擦除后出生 |
| RemoveBox | 本轮测试操作码3，提供旧min/size，在旧中心点擦除 |
| EraseBox | 体素布尔区域删除；盒体输出时由后端拆分相交旧盒；底层测试操作码2仅删除中心落在区域内的粒子 |
| ClearScene | 本轮测试操作码4，以覆盖整个逻辑空间的原生Trigger清空 |
| SetMotionGroup | 少量共享运动组；VRChat网络时间在Shader本地计算 |
| SetDisplay | 全局可见性和预上传外观包 |

首阶段SetBox载荷可使用minXYZ3、size减一3、style低/高2、tint1、motion1，共10槽。长度1–256，min+size≤256。坐标和尺寸需要真正进入原生粒子，不能只在Shader移动画面而使擦除地址错误。

Unity Shader外观参考布局RGBA每路先使用64级码：样式低/高、染色、运动组相位。资源包通过Unity导入器离线生成纹理/查找表，运行时切预上传内容。未取得资源包许可不视为默认附带原版资源。

## 删除与替换

普通单位粒子使用Trigger Inside=Kill，按格中心定位。长方体不能局部挖洞：后端改体素目标，拆分盒体，删除旧盒后重发碎片。三维减一格最多6盒，薄墙可4盒。第一阶段的`tools/compile_stage1.py`已提供最小几何编译器：从空场景开始，维护互不重叠盒体，支持绘制覆盖、区域布尔删除、最多6块拆分及容量预检；它尚不包含自动相邻合并、持久化场景台账、仿真视窗或发布服务。

当前Trigger radiusScale=0.0001，点擦除盒为0.025m³，闲时关闭Trigger。不同尺寸盒体可能有相同中心，接收器没有boxId索引；外部输出须为互不重叠的盒体分区，并维护旧min/size台账。尺寸改变时显式Remove旧盒再Set新盒，不能假定新中心会自动找到旧盒。极大盒体和密集中心的误删边界仍需扩展验证。

Ring Buffer在本轮调查中会保留被Kill的零寿命记录，未作为现行存储机制。现行普通模式配合`PositiveInfinity`出生寿命，让Kill走正常释放路径；容量回收以验收报告为准。

底层EraseRegion按粒子中心筛选，不会对大盒做几何裁剪。正式高层EraseBox必须找出**所有相交盒体**（包括中心在擦除区域外的盒体），Remove旧盒，再Set剩余碎片；空间中暂时出现空洞属于渐进模式，原子替换待双版本方案。

首测容量为64颗粒子，即最多64个盒体，不是64个逻辑体素。一个20×10×1盒体覆盖200格仍只占1粒子；相同体积若每格样式不同则可能占200粒子。容量已满时发送器未来应拒绝超额编译结果，不能依赖引擎自动丢弃行为保持权威目标。

材质仍为示例配色和程序化格纹理，没有实现资源包导入。Stage2已改为随盒体固定的UV重复，并验证多种姿态下纹理稳定；显示仍固定在Avatar模块坐标内，不是世界锚定。持续运动期间的编辑/擦除一致性、停用恢复等仍需独立验证。

## 显示与后台

渐进：命令完整后更新可见内容。staged：隐藏版本接收，完成后切换；须另有版本隔离和接收完整判据，首阶段不宣称已实现。

后台刷新持续读取Published目标，包含空格/删除，模型完成后继续。晚加入恢复、分片、序号回绕和多客户端仍是后续验证；单次OSC回读不等于远端确认。

## 执行阶段

1. **已完成Stage1**：原生粒子→OSC Int/Animator→单位体素与非均匀盒体→擦除/替换；有Editor证据与用户旧版客户端观察。
2. **已完成Stage2的Editor验证**：MF2单次提交、本地待执行槽、缩短执行流程、盒体UV修复；新版资源已准备，客户端更新后再单列现场结果。
3. 共享通道预算配置、分片与接收完整性；外部快速仿真、稀疏体素自动合并盒体、Draft/Published与独占调度，复用已有盒体布尔拆分。
4. 模型工具、截图迭代、多轮记忆、持续刷新与性能扩容。

## Stage3 定位与手动编辑实现

定位球、传感器和体素内容共用AnchorPose；只有体素ContentScale受MF_Scale影响。MA注入世界固定／显示／缩放／复位／持握5个同步参数，新增19bit，整套196bit。4层定位控制器与3层MF2组合；原生Contact+Gesture驱动本人持握结果，观察者读取同步MF_Grab。主约束冻结／重新烘焙抓取偏移；独立ResetGuide处理回到面前，不动画offset。详见[定位设计和边界](stage3/README.md)。

手动编辑器实现草稿、已发送台账、独占OSC线程、编辑合并、任意区域相减和同样式相邻盒合并，保持0.25s默认节拍。网页不持锁等待发包。已发送仅代表本机UDP发送，精确ACK／定期晚加入刷新／AI工具接口／原子快照切换仍待实现。详见[使用与API](editor/README.md)。
